    第2回で決めたI/Oを使って、CV01〜CV04の搬送を「いつ始めるか・何を見ながら動かすか・何をもって完了とするか」に分解します。

    1区間の考え方を見るインターロックを見る

    今回決めること

    • 3つの区間搬送の開始・完了条件
    • 隣接区間の搬送インターロック
    • 待機とタイムアウトの分け方

    使うI/O

    • X0〜X7：存在・通過センサ
    • X10：投入完了
    • Y0〜Y13：CVとストッパ

    今回はまだやらないこと

    • GX Works2へのラダー入力
    • 加工ステーションの動作確定
    • 実機の安全回路・試運転

    第3回でわかること

    1区間の基本CV01→CV023区間への展開インターロック待機とタイムアウト加工側への受け渡し

    1. 搬送制御は「1区間の受け渡し」から考える

    CV01〜CV04を一度に考えると条件が混ざりやすいので、まず搬送元 → 搬送先の1区間だけを設計します。ここでは「開始」「搬送中」「完了」の3状態に分けます。

    開始搬送元にワークがあり、搬送先が受け入れ可能かを確認する。
    搬送中必要なCVとストッパを搬送許可状態にし、通過の変化を監視する。
    完了通過確認と搬送先の存在確認がそろったら、搬送状態を終了する。

    最初に「完了条件」を決める

    モータを動かす条件だけではなく、何を確認したら止めるのかまでセットで決めます。これが曖昧だと、後でラダーを書いたときに搬送状態が終わらない、または早く終わる原因になります。

    先輩「動かす条件」だけじゃなくて、「終わったと判断する条件」まで先に決めるのが大事です。
    後輩開始と完了を分けると、ラダーにする前でも動きが見えてきますね。

    2. CV01→CV02を最初のひな形にする

    最初の区間では、CV01にワークがあり、CV02が受け入れ可能で、投入完了が確認できたときに搬送要求を成立させる考え方にします。

    段階見る条件制御の考え方
    開始前X0：CV01存在 / X2：CV02存在 / X10：投入完了CV01にワークがあり、CV02が空き、投入完了していることを確認する。
    搬送開始共通運転許可 + 隣接搬送が動作していないCV01→CV02の搬送状態を開始する。
    搬送中X1：CV01通過 / X2：CV02存在必要なCVを運転し、ストッパを搬送許可位置にして受け渡しを監視する。
    完了X1が一度ON後にOFF + X2がONCV01から抜け、CV02に到着したことを確認して搬送状態を終了する。

    ストッパ出力のON/OFF極性はまだ決め打ちしない

    第2回ではY4〜Y13をストッパ用出力として割り付けましたが、電磁弁の方式や機械側の保持方向によって「Y ONで解除」かどうかは変わります。ここでは保持位置／搬送許可位置として設計し、実際の出力極性は機器仕様が確定してから決めます。

    3. 同じ型をCV02→CV03、CV03→CV04へ展開する

    CV01→CV02で作った考え方を、そのまま下流へ展開します。区間ごとに違うロジックを作るのではなく、見るセンサと動かすCVを置き換える方が設計を追いやすくできます。

    CV01 → CV02

    搬送元 X0 / 通過 X1 / 搬送先 X2。投入完了 X10を開始条件へ追加。

    CV02 → CV03

    搬送元 X2 / 通過 X3 / 搬送先 X4。CV03が受け入れ可能なら開始。

    CV03 → CV04

    搬送元 X4 / 通過 X5 / 搬送先 X6。CV04が受け入れ可能なら開始。

    搬送搬送元存在通過確認搬送先存在主なCV出力
    CV01→CV02X0X1X2Y0・Y1
    CV02→CV03X2X3X4Y1・Y2
    CV03→CV04X4X5X6Y2・Y3

    上表は搬送の関係を整理するための設計表です。実機でモータやストッパを動かす回路・安全条件・機器定格は別途確認が必要です。

    4. 隣接区間は同時搬送させない

    このプロジェクトでは、同じCVを共有する隣接搬送を同時に開始させません。たとえばCV01→CV02とCV02→CV03はCV02を共有するため、どちらか一方だけを動かします。

    組み合わせ同時搬送理由
    CV01→CV02 と CV02→CV03しないCV02を共有する隣接搬送だから。
    CV02→CV03 と CV03→CV04しないCV03を共有する隣接搬送だから。
    CV01→CV02 と CV03→CV04条件がそろえば可能搬送区間を直接共有しないため。

    「全部直列」にはしない

    安全に順番を整理するために隣接区間は競合させませんが、離れた区間まで一律に止める必要はありません。将来のサイクルタイム改善を考え、競合しない搬送は並行できる余地を残します。

    5. 「下流待ち」と「搬送タイムアウト」を分ける

    CV02にワークが残っていてCV01が待っている状態は、まだ搬送指令を出していないので故障ではありません。一方、搬送を開始したのに所定の状態変化が確認できない場合は、タイムアウト候補として扱います。

    状態タイマを始めるか扱い
    下流が空くのを待っている始めない正常な待機状態
    搬送指令を出して受け渡し中始める搬送監視中
    搬送開始後、必要なセンサ変化が来ない監視時間超過で判定異常処理の候補

    タイムアウト秒数はここでは固定しない

    実際の監視時間は搬送距離、コンベヤ速度、ワークの挙動、センサ位置などで変わります。第3回では「いつ監視を開始し、何を確認して解除するか」まで決め、具体的な秒数は実機条件に合わせて後工程で設定します。

    6. CV04から加工エリアへは「受け渡し条件」だけ決める

    第3回ではCV04までの搬送制御を完成させます。加工エリア側のクランプ、穴あけ、加工完了などの細かなシーケンスは第4回で決めるため、ここではCV04のワークをいつ加工側へ渡してよいかという境界だけを整理します。

    第4回へ渡す条件

    CV04にワークが到着したら、加工側が受け入れ可能になるまでCV04で保持します。加工側の「受入可」が成立して初めて次の動作へ進む、というインターフェースにしておけば、搬送と加工を別々に設計できます。

    メーカー公式資料で確認

    このシリーズで想定するFX3U系のプログラム実装では、三菱電機「FX3S・FX3G・FX3GC・FX3U・FX3UCシリーズ プログラミングマニュアル［基本・応用命令解説編］」（Ver.V / JY997D11701-V / 2021年4月）を一次資料として確認します。第3回では内部状態を意味で整理し、M・Tなどの具体的なデバイス割付と命令への落とし込みは最終実装時に公式資料と照合して確定します。三菱電機公式・MELSEC-Fプログラミングマニュアル一覧を見る

    7. 第3回のまとめ

    搬送制御は、出力を直接ON/OFFするところから始めるのではなく、区間ごとの開始条件・搬送状態・完了条件を先に固定すると整理しやすくなります。

    STEP 11区間の開始と完了を決める搬送元・通過・搬送先の3点で考える
    STEP 2同じ型を3区間へ展開する条件の役割をそろえて読みやすくする
    STEP 3待機と異常監視を分ける搬送開始後だけタイムアウトを監視する
    設計項目第3回で決めたこと
    区間搬送CV01→02、CV02→03、CV03→04を同じ考え方で構成
    完了条件通過センサのON→OFFと搬送先の存在を組み合わせる
    競合防止隣接区間の搬送は同時に行わない
    並行動作競合しない離れた区間は条件次第で並行可能
    異常監視下流待ちは正常待機、搬送開始後の不成立をタイムアウト候補とする
