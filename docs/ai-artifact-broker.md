# AI Artifact Broker v0.1

## Purpose

`ai-artifacts` is a private, temporary Supabase Storage bucket used only to move reviewed image artifacts from AI systems to the constrained GitHub artifact writer.

The durable source of truth remains GitHub. Supabase is not an image archive and is not part of the public site delivery path.

## Architecture

```text
AI / image generator
  -> common orchestrator / adapter
  -> Artifact Broker: create_upload
  -> signed upload URL
  -> private Supabase bucket: ai-artifacts
  -> Artifact Broker: prepare_download
       - max size check
       - WebP/PNG/JPEG magic-byte check
       - extension/content match
       - SHA-256 verification
  -> 10-minute signed download URL
  -> GitHub AI Artifact Writer
       - branch/path/host checks
       - SHA-256 verification again
       - image signature verification again
  -> preview branch
  -> delete temporary Supabase object through cleanup-only credential
  -> Netlify Deploy Preview
  -> human final review
  -> production only after the existing publication gate
```

## Security boundary

- Bucket: `ai-artifacts`
- Bucket remains private.
- Bucket UI limits uploads to 5 MiB and MIME types `image/webp`, `image/png`, `image/jpeg`.
- No Supabase service-role key is given to GPT, Claude, Gemini, image models, or other producer agents.
- The Edge Function alone uses `SUPABASE_SERVICE_ROLE_KEY` to operate the private bucket.
- Producer/orchestrator calls use `ARTIFACT_BROKER_TOKEN` only for `create_upload` and `prepare_download`.
- GitHub cleanup uses a different `ARTIFACT_CLEANUP_TOKEN` that is accepted only for `delete`.
- Broker accepts only generated object paths under `incoming/YYYY-MM-DD/<uuid>/...`.
- Object names are restricted to simple ASCII filenames.
- `prepare_download` must receive the producer's expected SHA-256 and verifies the stored bytes before issuing a download URL.
- Download URLs are valid for 10 minutes.
- Signed upload URLs are generated by Supabase and expire according to Supabase's signed-upload behavior.
- GitHub Writer independently verifies SHA-256, actual file signature, branch prefix, repository path, and allowed host.
- `main` remains forbidden to the artifact writer.
- The broker is a transport/security boundary, not proof that editorial/image review happened. Upstream orchestration must invoke it only for an artifact that passed the image/content quality gate.

## Edge Function authentication

`supabase/config.toml` sets `verify_jwt = false` for this function because the broker uses its own narrowly scoped credentials rather than distributing Supabase user/service credentials to producer systems.

This does **not** make the broker unauthenticated. Every supported action checks `x-artifact-broker-token` against the action-specific secret before Storage access occurs.

## Broker endpoint

Implementation:

`supabase/functions/artifact-broker/index.ts`

The function accepts authenticated `POST` JSON requests with one of three actions.

### `create_upload`

Input fields:

- `action`: `create_upload`
- `file_name`: `.webp`, `.png`, `.jpg`, or `.jpeg`
- `mime_type`: `image/webp`, `image/png`, or `image/jpeg`

Credential: `ARTIFACT_BROKER_TOKEN`.

Returns an opaque object path plus a signed upload URL.

### `prepare_download`

Input fields:

- `action`: `prepare_download`
- `object_path`: exact object path returned by `create_upload`
- `sha256`: 64-character hexadecimal digest of the original artifact

Credential: `ARTIFACT_BROKER_TOKEN`.

The broker downloads the private object, checks size/signature/extension/SHA-256, and returns a 10-minute signed download URL.

### `delete`

Input fields:

- `action`: `delete`
- `object_path`: exact object path

Credential: `ARTIFACT_CLEANUP_TOKEN`.

This is called by GitHub Writer only after the artifact transfer/commit step succeeds.

## Required secrets

The function expects:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ARTIFACT_BROKER_TOKEN`
- `ARTIFACT_CLEANUP_TOKEN`

Both custom tokens must be independent random secrets of at least 32 characters. They must never be committed to the repository or pasted into documentation, PR comments, preview pages, or AI prompts.

Supabase supplies its project URL/service-role context to deployed Edge Functions; deployment must confirm the actual environment before enabling the broker.

## GitHub Writer connection

The existing `.github/workflows/ai-artifact-writer.yml` uses these repository settings:

- variable `AI_ARTIFACT_ALLOWED_HOSTS`: exact hostname used by Supabase signed download URLs
- variable `ARTIFACT_BROKER_URL`: exact deployed Edge Function HTTPS URL
- secret `ARTIFACT_CLEANUP_TOKEN`: cleanup-only token, matching the Edge Function secret

Do not allow `*.supabase.co` in `AI_ARTIFACT_ALLOWED_HOSTS`; use the exact signed-download hostname only.

The writer receives:

- `artifact_url`: broker-produced signed download URL
- `sha256`: verified digest
- `target_branch`: existing `ai-`, `preview-`, or `pilot-` branch
- `target_path`: under `assets/images/`
- `commit_message`
- optional `cleanup_object_path`: exact temporary object path

After the repository transfer/commit step succeeds, the workflow calls the fixed `ARTIFACT_BROKER_URL` with the cleanup-only secret and deletes that object. The cleanup call does not follow redirects.

## Cleanup policy

Normal flow deletes the temporary object only after the GitHub writer transfer/commit step succeeds. A failed transfer keeps the object for retry until a later cleanup pass.

A later revision may add a scheduled stale-object cleanup as defense in depth. It must use a safe age threshold and must not delete an object still needed by an in-flight transfer.

## Current deployment gate

This repository change installs the broker implementation and cleanup integration but does not deploy the Edge Function and does not add any secret or repository variable.

One-time human/admin configuration is still required for Supabase function deployment/secrets and GitHub variables/cleanup secret. Secret values must not be sent in chat.

The provider-neutral connector/plugin/orchestrator adapter that sends a local AI-produced binary to the signed upload URL is a separate remaining integration step. Supabase alone does not give a normal ChatGPT session a generic authenticated binary-upload tool.
