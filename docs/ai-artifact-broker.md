# AI Artifact Broker v0.1

## Purpose

`ai-artifacts` is a private, temporary Supabase Storage bucket used only to move reviewed image artifacts from AI systems to the constrained GitHub artifact writer.

The durable source of truth remains GitHub. Supabase is not an image archive and is not part of the public site delivery path.

## Architecture

```text
AI / image generator
  -> Artifact Broker: create_upload
  -> short-lived signed upload URL
  -> private Supabase bucket: ai-artifacts
  -> Artifact Broker: prepare_download
       - max size check
       - WebP/PNG/JPEG magic-byte check
       - extension/content match
       - SHA-256 verification
  -> 10-minute signed download URL
  -> GitHub AI Artifact Writer
       - branch/path/host checks
       - SHA-256 verification again
       - image signature verification again
  -> preview branch
  -> Netlify Deploy Preview
  -> human final review
  -> production only after the existing publication gate
  -> Artifact Broker: delete after confirmed GitHub transfer
```

## Security boundary

- Bucket: `ai-artifacts`
- Bucket remains private.
- Bucket UI limits uploads to 5 MiB and MIME types `image/webp`, `image/png`, `image/jpeg`.
- No Supabase service-role key is given to GPT, Claude, Gemini, image models, or other producer agents.
- The Edge Function alone uses `SUPABASE_SERVICE_ROLE_KEY` to operate the private bucket.
- Producers use only a broker credential with narrowly constrained broker actions.
- Broker accepts only generated object paths under `incoming/YYYY-MM-DD/<uuid>/...`.
- Object names are restricted to simple ASCII filenames.
- `prepare_download` must receive the producer's expected SHA-256 and verifies the stored bytes before issuing a download URL.
- Download URLs are valid for 10 minutes.
- Signed upload URLs are generated by Supabase and expire according to Supabase's signed-upload behavior.
- GitHub Writer independently verifies SHA-256, actual file signature, branch prefix, repository path, and allowed host.
- `main` remains forbidden to the artifact writer.

## Broker endpoint

Implementation:

`supabase/functions/artifact-broker/index.ts`

The function accepts authenticated `POST` JSON requests with one of three actions.

### `create_upload`

Input fields:

- `action`: `create_upload`
- `file_name`: `.webp`, `.png`, `.jpg`, or `.jpeg`
- `mime_type`: `image/webp`, `image/png`, or `image/jpeg`

Returns an opaque object path plus a signed upload URL.

### `prepare_download`

Input fields:

- `action`: `prepare_download`
- `object_path`: exact object path returned by `create_upload`
- `sha256`: 64-character lowercase/uppercase hexadecimal digest of the original artifact

The broker downloads the private object, checks size/signature/extension/SHA-256, and returns a 10-minute signed download URL.

### `delete`

Input fields:

- `action`: `delete`
- `object_path`: exact object path

This is called only after the artifact is confirmed in the intended GitHub preview branch.

## Required secrets

The function expects:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ARTIFACT_BROKER_TOKEN`

`ARTIFACT_BROKER_TOKEN` must be a random secret of at least 32 characters and must never be committed to the repository or pasted into documentation, PR comments, preview pages, or AI prompts.

Supabase provides the project URL/service-role context to deployed Edge Functions; deployment must confirm the actual environment before enabling the broker.

## GitHub Writer connection

The existing `.github/workflows/ai-artifact-writer.yml` requires repository variable `AI_ARTIFACT_ALLOWED_HOSTS`.

For the current Supabase project, add only the exact Storage hostname used by signed download URLs. Do not allow `*.supabase.co` and do not use a wildcard.

The writer should receive:

- `artifact_url`: broker-produced signed download URL
- `sha256`: verified digest
- `target_branch`: existing `ai-`, `preview-`, or `pilot-` branch
- `target_path`: under `assets/images/`
- `commit_message`

## Cleanup policy

Normal flow deletes the temporary object only after the GitHub writer has committed it successfully. A failed transfer keeps the object for retry until a later cleanup pass.

A later revision may add a scheduled stale-object cleanup as a defense-in-depth measure. It must never delete an object that is still needed by an in-flight transfer.

## Current deployment gate

This repository change only installs the broker implementation and documents the boundary. It does not deploy the Edge Function and does not add any secret.

Human/admin action is still required for the one-time Supabase function deployment/secret configuration and GitHub repository variable/secret configuration. Those values must not be sent in chat.
