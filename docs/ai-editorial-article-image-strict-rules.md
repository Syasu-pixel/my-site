# Denkicontrol AI編集部 記事制作・画像品質 絶対ルール v3

## 1. 目的
この文書は、新規記事のHTML構造、共通UI継承、画像生成、HTML内部監査、Preview完成条件を曖昧にしないための実装ルールである。

`docs/ai-editorial-master-rules.md` の補強規則として扱い、記事制作時は必ず参照する。

## 2. 新規記事のコピー元
- 新規記事は `articles/short-ground-leakage-basic.html` を標準コピー元とする。
- 制作開始時に必ずGitHub main上のコピー元実ファイルを取得し、ファイル単位で複製して開始する。
- 「参考にする」「雰囲気を似せる」「同等のHTML/CSSを新しく書く」は禁止する。
- コピー元を取得できない場合は制作を開始しない。
- 将来、標準コピー元を変更する場合は管理者承認を必要とし、別案件でルールを更新する。

## 3. 変更可能範囲
原則として変更してよいのは次だけとする。
- 記事タイトル / h1
- `title`
- meta description
- canonical / hreflang / OGP / Twitter Card等の記事固有meta
- robots（Previewと本番の運用ルールに従う）
- 本文
- 見出し
- 記事固有画像
- 画像alt
- 関連記事のリンク先・タイトル・説明
- 記事固有ID / anchor
- slug / 記事固有URL
- 記事固有の構造化データ
- パンくず内の現在記事名・記事固有URL

## 4. 変更禁止の共通UI
次の構造・CSS・class・挙動はコピー元からそのまま継承し、記事単体で再設計しない。
- ヘッダー
- ロゴ周辺
- 検索UI / 検索機能
- 言語切替
- パンくずの構造・デザイン
- ページ全体のカラム構造
- 右サイドバー
- 寄付 / 応援導線
- 関連記事カードのHTML構造・CSS
- 先輩・新人の会話UI構造
- フッター
- 共通ボタン
- 共通カード
- breakpoint
- PC / タブレット / スマホ用レスポンシブCSS
- 共通class名
- 共通余白・角丸・影・フォント等のデザインシステム

共通UIを変更したい場合は、新規記事内で変更せず「共通UI変更案件」として別途提案する。

## 5. HTML差分監査
Preview作成前にGPTがコピー元HTMLと新記事HTMLを直接比較する。

最低限、次を監査する。
- 共通構造のDOM差分
- 共通classの欠落・追加・改変
- 共通CSSの意図しない再定義
- ヘッダー / 検索 / 言語切替
- パンくず
- カラム構造
- 右サイドバー
- 寄付導線
- 関連記事UI
- 会話UI
- フッター
- レスポンシブCSS
- `title`
- meta description
- canonical
- robots
- OGP
- Twitter Card
- hreflang
- 構造化データ
- h1〜h3見出し階層
- 画像alt
- 内部リンク
- 外部リンクの `target` / `rel`
- 重複ID
- 画像・リンク・参照ファイルの実在

共通UIに意図しない差分がある場合は自動修正へ戻し、管理者確認へ送らない。

## 6. 画像を作る前の用途判定
「画像枚数を埋めるため」に生成しない。ただし、本文を文字だけで説明できるからという理由で図解を省略してはならない。

### AI生成画像を優先するもの
- hero
- OGP
- 情景イラスト
- キャラクターを使った概念説明
- 視覚的な雰囲気・状況理解が重要な説明
- 比較・使い分けを初心者が一目で理解するための教材インフォグラフィック
- 原理・構造・部品関係・動作順序を一枚で理解させる図解
- 導入手順・確認手順・トラブル切り分けを、アイコン・人物・装置図を使って直感的に示す教材画像

### HTML / CSS / SVGを優先するもの
- 数値を正確に読ませる表
- 細かな仕様一覧
- 検索・コピー・アクセシビリティ上、テキストとして保持すべき情報
- 形状や寸法を厳密に表す必要があり、生成画像では誤差が許されない技術図

### 表現手段の判断原則
- `比較 / 手順 / フロー / チェックリスト` という形式だけで自動的にHTML/CSS/SVGへ振り分けない。
- 初心者理解に視覚化が有効なら、比較・手順・フロー・チェックリストでもAI生成インフォグラフィックを優先してよい。
- HTML表とAI図解は排他的ではない。数値・仕様はHTML表、概念理解は図解画像という併用を推奨する。
- 「文章で読めば分かる」ではなく、「画像だけ見ても大筋が分かるか」を基準にする。

### 実画像生成の必須条件
- 「AI生成画像として制作する」と判定した成果物は、必ず実際の画像生成モデルを実行して画像そのものを生成する。
- テキスト生成モデルがSVGコード、HTML、CSS、図形コードを作っただけの成果物を「AI画像生成完了」と記録してはならない。
- hero / OGP / 教材インフォグラフィック / 情景イラスト / キャラクター入り概念画像を、簡易SVGで代替して画像生成工程を省略してはならない。
- 画像生成モデルを実行できない状態では、その画像は `未生成` と扱う。ダミー画像や簡易SVGを置いてPreview完成扱いにしない。
- 生成後はGPTがファイル名・プロンプト・仕様だけで判定せず、生成された実画像のピクセル内容を視覚的に確認する。
- GPTが実画像を視覚確認できていない場合、その画像は品質ゲート未通過とする。
- 視覚確認でNGの場合は、同じプロンプトを機械的に繰り返さず、構図・情報量・視線誘導・余白・キャラクター配置・色調・文字量・図解密度の原因を分析して実画像を再生成する。
- 採用済みheroは後続生成画像の視覚アンカーとして扱い、キャラクターを含む後続画像では正本キャラクターテンプレートと採用heroの両方を参照する。
- 目的は「画像ファイルを作ること」ではなく、従来のChatGPT対話型画像制作と同等の `生成 → 実画像確認 → 修正設計 → 再生成 → 採用` ループをAI編集部内でも実行することである。

## 7. ゴールドスタンダード画像
Denkicontrolの本文図解品質は、次の既存採用画像セットを基準とする。

`assets/images/star-delta-start-basic/`
- `star-delta-start-overview.webp`
- `dol-vs-star-delta-start.webp`
- `star-delta-switching-sequence.webp`
- `star-delta-voltage-current-torque.webp`
- `star-delta-circuit-reading-guide.webp`
- `star-delta-troubleshooting-guide.webp`

### ゴールドスタンダードから継承する品質特性
- 記事テーマが一目で分かる大きな見出し
- 主役となる機器・動作・比較対象が明確
- 青系を軸に、緑・橙・紫・赤を補助色として整理して使う
- アイコン、矢印、番号、囲み、吹き出し等で視線の順序が自然
- 文章をそのまま画像へ詰め込まず、短いラベルと視覚要素で理解させる
- 必要に応じて先輩・後輩キャラクターを案内役として使う
- 1枚の中に `タイトル → 主図 → 要点/手順 → 注意` の情報階層がある
- ただの写真風背景ではなく、教材として説明力のある構成
- PCで見栄えし、スマホ縮小でも主題と主要ラベルが残る
- 本文を読まなくても、その節の大筋を画像だけで理解できる

### ゴールドスタンダード比較監査
- IMAGE REVIEWERは点数だけでなく、上記採用画像群と並べて見劣りしないかを判定する。
- `雰囲気画像としては綺麗` でも `教材として説明力が弱い` 場合は不合格とする。
- 白背景に装置を置いただけ、薄い背景写真だけ、箱と矢印だけ、文字カードだけの画像はゴールドスタンダード未達とする。
- ゴールドスタンダードに対して、情報設計・視線誘導・図解密度・親しみやすさのいずれかが明確に劣る場合は再生成する。

## 8. hero画像ルール
- 原則必須。
- 記事テーマを一目で理解できる。
- 単なる文字入りカードではなく、記事内容を視覚化したイラストとして成立させる。
- HTMLのh1・リード文が左側に重なる前提で構図を設計する。
- 左側に重要人物・重要文字・重要機器を置かない。
- 背景として敷いても内容が消えないコントラストを確保する。
- 白く飛んで図が見えない、薄すぎる、情報が判別できないheroは不採用。
- キャラクターを含む場合は正本テンプレートを必ず参照する。
- heroをAI生成画像として制作する場合、画像生成モデルによる実画像生成とGPTによる実画像視覚確認を必須とする。

## 9. OGPルール
- heroと別用途として制作する。
- SNSや検索共有で小さく表示されてもテーマが分かる。
- 長文・小さい文字・細かい表を入れない。
- 本番用OGPはサイトの既存運用に合うWeb向け画像形式で用意する。
- 単なる簡易SVGを本番OGPとして扱わない。
- metaから正しい画像ファイルを参照していることをGPTが監査する。
- OGPをAI生成画像として制作する場合も、実際の画像生成モデルによる生成と実画像視覚確認を必須とする。

## 10. 本文画像ルール
- 本文が長くなりやすい記事ほど、理解の節目に図解を入れる。
- 新規初心者向け記事では、本文用の主要図解を原則2〜5枚候補設計する。不要な場合は理由を内部記録する。
- 1画像1メッセージを原則としつつ、教材インフォグラフィックでは同一テーマ内の比較・手順・注意を一枚に階層化してよい。
- 一見して「何を説明しているか」が分かる。
- 本文をそのまま画像内にコピーしただけの画像は禁止。
- 長文、小さい注釈、細かすぎる表は禁止。
- スマホ幅でも主要要素が読めること。
- 比較節では、数値表だけで終えず、視覚比較図の生成候補を必ず検討する。
- 原理・構造・用語説明では、位置関係や動作が図で理解できるなら説明図を優先する。
- 手順節では、番号・アイコン・矢印・装置図・人物等を使ったステップ図を候補とする。
- トラブル切り分けでは、確認順序を視覚的に追えるチェック/フロー図を候補とする。
- 画像生成よりHTML/CSS/SVGの方が正確性・可読性・アクセシビリティで明確に優れる場合だけ、画像を省略してよい。
- AI生成画像として作る本文画像は、生成後の実画像視覚確認を必須とする。

## 11. キャラクター画像ルール
- 人物を含む生成画像では `assets/images/character-templates/senpai-kouhai-character-template.png` を正本として必ず参照する。
- HTML会話UIでは `assets/images/guide-characters/` の既存画像を使う。
- 生成用テンプレートと会話UI素材を混同しない。
- 新しい別キャラクターを勝手に作らない。
- 表情・ポーズ・作業場面は変更可だが、顔・服装・ヘルメット・頭身・絵柄・役割は維持する。

## 12. 画像ファイル形式
- AI生成したビジュアルはWeb向けPNG/WebP等へ整える。
- SVGはコードで正確に描く図解用途を主とする。
- AIが作った簡易図をSVGで保存しただけのものを「高品質な画像生成」と扱わない。
- hero / OGP / 教材インフォグラフィックと、情報図解SVGを明確に分ける。

## 13. 画像品質ゲート
数値だけの自己評価で通過させない。

### 必須の4段階
1. 生成担当が生成された実画像そのものを視覚確認して自己評価
2. ゴールドスタンダード画像群との比較
3. 独立IMAGE REVIEWERが実画像そのものを視覚確認
4. HTML組込み後のPreviewレビュー

ファイル名、プロンプト、alt、生成ログ、仕様書だけを読んで画像品質を合格判定してはならない。

### 判定項目
- 技術的正確性
- 文字可読性
- キャラクター一致
- 構図
- 用途一致
- 記事との関連性
- 既存サイトとの統一感
- スマホ視認性
- 背景として使用したときの視認性
- 教材としての説明力
- 視線誘導
- 情報階層
- ゴールドスタンダード比での完成度

### 本文図解の合格条件
- 画像単体で節の大筋を説明できる。
- 画像を見ることで本文を読む前の理解が明確に進む。
- ただの装飾、雰囲気、文字カードではない。
- 比較なら違いが視覚で分かる。
- 手順なら順番が視覚で追える。
- 原理なら位置・流れ・関係が視覚で分かる。
- トラブル対応なら確認順が視覚で追える。

重大NGが1つでもあれば再制作する。

## 14. 関連記事
- HTML構造・CSSはコピー元から完全継承する。
- 記事ごとに変更するのはリンク先・タイトル・説明だけ。
- GitHub main上で実在する記事のみ使う。
- 関連性の弱い記事を枚数合わせで入れない。

## 15. 寄付・応援導線
- コピー元のHTML / CSS / 文言 / リンク属性を原則そのまま継承する。
- 記事ごとに簡略版を作らない。
- 「似たデザインの寄付ボタン」を新しく実装することは禁止。

## 16. Preview完成条件
次の全条件が揃うまで `Preview完成` / `NEEDS_HUMAN` と判定しない。
- 記事本文完成
- 技術監査合格
- SEO / meta監査合格
- HTML内部監査合格
- コピー元構造一致確認
- 必要なAI生成画像について画像生成モデル実行済み
- 必要なAI生成画像をGPTが実画像として視覚確認済み
- 初心者向け記事で本文図解候補2〜5枚を検討済み
- 比較 / 原理 / 手順 / トラブル切り分け等、視覚化効果が高い節に必要な教材図解がある
- ゴールドスタンダード比較監査済み
- 必要画像完成
- 画像品質ゲート合格
- 画像組込み完了
- 内部リンク・外部リンク検査合格
- 画像パス実在確認
- PC表示確認
- スマホ表示確認
- 寄付導線確認
- 関連記事確認
- 会話UI確認
- Preview環境でのnoindex確認
- Previewデプロイ正常

## 17. 管理者へ出す前のGPT監査
- GPTがHTMLソースとPreviewを先に監査する。
- 画像については、生成された実画像とPreviewへ組み込まれた状態の両方を確認する。
- 文字ばかりで図解不足になっていないかを確認する。
- ゴールドスタンダード画像群と比較して、教材として見劣りしないか確認する。
- 明確なNGがあれば管理者へ出さず自動修正へ戻す。
- GPT監査を通ったものだけを管理者の最終Preview確認へ送る。
- 管理者確認では、見た目・画像・読みやすさ・サイトらしさ・スマホ表示を含めて最終判断する。

## 18. 禁止事項
- コピー元を見ずに新規HTMLをゼロから作る。
- 共通UIを「似せて」再実装する。
- 記事単体で共通CSSを再設計する。
- 寄付導線・関連記事・会話UIを簡略化する。
- 画像枚数を満たすためだけに生成する。
- `比較 / 手順 / フロー / チェックリストだからHTMLで十分` と機械的に判断し、教材図解の検討を省略する。
- 初心者向け記事を文字と表だけで構成し、視覚化できる主要概念を図解しない。
- 簡易SVGを高品質画像として水増しする。
- AI生成画像として計画した成果物をSVG/HTML/CSSだけで代替し、画像生成完了と記録する。
- 生成画像の実物を視覚確認せず、プロンプトやファイル名だけで品質合格とする。
- ゴールドスタンダードとの比較をせず、点数だけで画像を合格させる。
- 画像生成モデルを実行できていないのにダミー画像でPreview完成扱いにする。
- HTML内部監査なしでPreview完成扱いにする。
- 画像品質ゲート未通過で管理者確認へ送る。
