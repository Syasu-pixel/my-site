# Denkicontrol AI編集部 記事難易度・キャラクター運用ルール v1

## 1. 目的
この文書は、AI編集部が新規記事を「初心者向け固定」で量産せず、サイト全体の充足度に応じて beginner / intermediate / advanced を選定するための実装ルールである。

`docs/ai-editorial-master-rules.md`、`docs/ai-editorial-article-image-strict-rules.md` を補強する運用ルールとして扱う。

## 2. 新規記事は初心者向け固定にしない
- 新規記事作成時に、必ず `beginner / intermediate / advanced` の難易度を明示してから制作する。
- 「新規記事 = 初心者向け」の固定ルールは禁止する。
- 既存の初心者向け記事が十分に存在するテーマで、内容の近い beginner 記事を重ねて作らない。
- beginner 記事は、サイト内に明確な基礎穴がある場合、既存記事では検索意図を満たせない場合、または中級・上級記事の前提知識として不足している場合に限定して優先する。
- beginner を選ぶ場合は、制作前に「なぜ既存初心者記事では不足するのか」を内部記録する。

## 3. 難易度の選定優先順位
AI編集部は記事候補を決める前に、既存記事・backlog・カテゴリ構成・内部リンク・検索意図を確認し、次の順で判断する。

1. 同テーマの初心者向け記事が不足しているか
2. 初心者向け記事は存在するが、実務判断・選定・トラブル対応が不足しているか
3. 中級記事は存在するが、設計・性能・安全・故障解析・複数機器連携等の深掘りが不足しているか
4. 既存記事とタイトル・検索意図・本文範囲が重複しないか

原則として、初心者記事が十分なテーマでは `intermediate` を第一候補とする。
`advanced` は、前提となる beginner / intermediate の導線があるテーマから優先して追加する。

## 4. beginner の定義
対象読者:
- 制御・電気の用語を学び始めた人
- 機器を初めて見る人
- まず全体像を理解したい人

主な内容:
- 用語
- 基本原理
- 機器の役割
- 基本的な違い
- 仕様表の入口
- 安全上の基本注意

表現:
- 先輩・後輩キャラクターを積極的に使用してよい。
- 会話UI、吹き出し、教材インフォグラフィックを多用してよい。
- 難しい概念を図解へ置き換え、本文だけに依存しない。
- 親しみやすさを重視するが、技術的な正確性を崩さない。

## 5. intermediate の定義
対象読者:
- 基礎用語は理解している人
- 実際の選定・設計・調整・保全・トラブル対応を行う人

主な内容:
- 機種・方式の選定
- 仕様比較と判断
- 設置条件
- 配線・I/O・信号の考え方
- パラメータ・設定の読み方
- トラブルシュート
- 誤動作・誤検出の切り分け
- 実務上の失敗例と確認順

表現:
- beginner と同様、キャラクターを多用してよい。
- ただしキャラクターは説明補助であり、技術判断そのものを軽く見せない。
- 比較、選定、切り分け、手順はゴールドスタンダード級の教材図解を積極的に使う。
- 「なぜその判断になるのか」を図・表・公式資料で示す。

## 6. advanced の定義
対象読者:
- 実務経験があり、設計根拠・性能・安全性・故障解析まで確認したい人
- 設備設計、立上げ、改善、保全、レビューを担当する人

主な内容:
- 応用設計
- 複数機器・複数信号の連携
- 制御方式比較
- 性能設計
- 安全設計・リスク評価の考え方
- 故障モード解析
- タイミング・応答・負荷・ノイズ等の設計判断
- 公式仕様・規格・設計条件を根拠にした深掘り
- 改善設計・再発防止

表現:
- 上級記事では全体トーンを beginner / intermediate より真剣・簡潔・技術文書寄りにする。
- キャラクターの多用は禁止する。
- 会話UIを使う場合も原則1か所程度の補助に留め、重要判断や安全事項をキャラクターの冗談・軽い表現で説明しない。
- hero / OGP でキャラクターを使う場合も、ポーズ・表情は落ち着かせ、遊びの強い演出を避ける。
- 本文図解はキャラクターより、回路、信号、タイミング、構造、比較、条件、因果関係を主役にする。
- 装飾目的の吹き出し、過度なアイコン、かわいさ優先の図解は避ける。
- 公式資料、数値、適用条件、前提、例外、注意事項の読みやすさを優先する。

## 7. キャラクター密度ルール
### beginner
- 多用可。
- hero、overview、comparison、check-flow、会話UIなどで自然に使ってよい。
- ただし1画像の主役がキャラクターだけにならないようにする。

### intermediate
- 多用可。
- 実務上の比較・確認・切り分けを案内する役として使ってよい。
- 技術図解の主役は機器・回路・信号・手順とし、キャラクターは補助役にする。

### advanced
- 最小限。
- 原則として本文の主要図解にはキャラクターを入れない。
- 会話UIを残す場合も1か所程度を目安とし、短い確認・導入に限定する。
- 安全判断、設計根拠、規格、故障解析、数値評価の説明ではキャラクター演出を使わない。

## 8. 記事制作前の必須記録
新規記事の制作前に、内部状態へ最低限次を保存する。
- `article_level`: `beginner | intermediate | advanced`
- `level_reason`: その難易度を選んだ理由
- `existing_beginner_coverage`: 同テーマの初心者記事の充足状況
- `existing_intermediate_coverage`: 同テーマの中級記事の充足状況
- `character_density`: `high | medium | low`
- `prerequisite_articles`: 前提として案内する既存記事

## 9. 火曜新規記事の既定方針
- 火曜の新規記事は beginner 固定にしない。
- 初心者向け基礎が十分なテーマでは intermediate を優先する。
- advanced 候補は、前提となる beginner / intermediate 記事と内部リンク導線が存在するテーマから選ぶ。
- 同じ難易度の記事だけを連続させず、サイト全体の beginner / intermediate / advanced の偏りを週次計画で確認する。

## 10. Preview監査
Preview前にGPTは、技術内容だけでなく難易度表現が適切かも監査する。

### beginner / intermediate
- 親しみやすさが不足していないか
- 図解が不足して文字壁になっていないか
- キャラクターが技術理解の補助として機能しているか

### advanced
- 軽すぎる表現になっていないか
- キャラクターや吹き出しが多すぎないか
- 技術根拠、公式資料、数値、条件、例外が主役になっているか
- 初心者向け説明を繰り返して記事密度を下げていないか

難易度と表現が一致しない場合は `NEEDS_HUMAN` へ送らず、自動修正へ戻す。

## 11. 禁止事項
- 新規記事を無条件に beginner とする。
- beginner の既存記事が十分なのに、タイトルだけ変えて類似基礎記事を増やす。
- advanced 記事をキャラクター・吹き出し・かわいい装飾中心にする。
- advanced 記事で技術根拠より親しみやすさを優先する。
- beginner / intermediate で文字説明だけに偏り、視覚的な理解支援を省略する。
