# AI編集部ちびキャラモーション テンプレルール
更新: 2026-09-08 / 仕様・引き継ぎ v0.1

## 目的と対象
対象リポジトリ: Syasu-pixel/my-site。
対象画面: /ai-editorial-dashboard/。
先輩・後輩が待機中は休憩や雑談、案件中は実際の工程に合った作業演出をする。
ユーザーは3台のモニターで作業し、隣のモニターの別ウィンドウに表示したまま眺める。
Work専用の機能に依存せず、Chatや別の開発環境からも、このファイルと同梱HTMLを読んで続けられる構成にする。
これは通常のプロジェクト仕様書であり、インストール型スキルではない。

## 採用したキャラクター
- 先輩: 白い安全ヘルメット、短い茶髪、茶色の目、青い作業服。頼れて丁寧、時々とぼける。
- 後輩: 青い十字付きヘルメット、茶色のボブ、茶色の目、薄い灰色の上着と青いズボン。まじめで素直、時々鋭くツッコむ。
- ユーザーが採用した絵柄と服装を維持。無断で別キャラや幾何学的な代用品に変更しない。
- 埋め込み素材は差分制作時の派生イラスト。元の採用画像と完全一致を保証するものではない。
- 場面ごとのサイズ・頭身・配色の揺れを仕上げ時に統一する。

## 合意済みの表示方針
| 状態 | 表示 |
| --- | --- |
| 対応中・要確認ともに0件 | 中央を待機用の編集室へ。過去の完了チャットを自動表示し続けない |
| 案件中 | 実際のチャットを主役にし、キャラは下端など専用スペースへ |
| 管理者確認待ち | 確認待ちとして停止。勝手に次の工程へ進めない |
| 完了済み案件を手動選択 | 履歴を表示。「編集室へ戻る」を用意 |
| 通信エラー・更新停止 | 活発に作業しているふりをやめ、不明・要確認を表示 |
| スマホ | 小さな専用スペース。文章・入力・ボタンを遮らない |
| 鑑賞用 | 編集室を広く表示するモードを検討 |

下の曜日テンプレート・依頼入力を維持。既存3カラムとログイン・案件操作を壊さない。
終端案件では「案件を閉じる」を表示しない方針。
部屋は淡い壁・床・左の出入口・右の給湯コーナーを基本に、既存の青いUIとなじませる。
絵コンテの部屋画像をそのまま完成背景として貼り込むことは未承認。背景・キャラ・家具を別レイヤーにする。

## 再生・時間のルール
- フォーカス喪失や別ウィンドウ操作を理由に停止しない。ユーザーは表示したまま眺める。
- 経過時間に基づき再生。描画コール数を時計にしない。
- 描画がブラウザに抑制された場合は、復帰時に現在時刻の場面へ追従。大量の早送り・通知・発言を再生しない。
- 手動一時停止では時間も止める。再開後の飛びを避ける。
- 音声なしを初期値とする。自動音声再生は追加しない。
- OSの動きを減らす設定に配慮し、明示的な再生操作を用意。
- 台詞は1発言8秒を採用した試作値。文字量に合わせ調整し、横目で読める大きさにする。
- 実端末での60fpsを目標とするが保証しない。3画面でのCPU/GPU負荷を測る。

## 会話・小芝居の重複防止（未実装）
目標: 2時間、同じ会話セット・一連の小芝居を再生しない。裏タブの経過も含める。
呼吸・歩行・まばたきなどの基本動作の繰り返しは許容。
目安: 会話200本、小芝居40本、基本動作20〜30種。これらは計画数であり完成数ではない。
会話は文単位のランダム結合をせず、整合する4〜8発言のセットとして作る。
話題・オチ・演出の連続も避ける。履歴は再読み込み後も保持し、保存が使えない場合も安全に動く。
候補が不足する場合は静かな待機動作に戻す。重複禁止を破って無理に発言しない。
会話開始の間隔は45〜90秒程度を検討。試作の短いループは本番仕様ではない。
仕事用会話は工程別に分ける。AI APIを毎回呼ばず、まずローカル台本で実現する。

## 実案件との連動（未実装）
受付→企画→調査→制作→検証→管理者確認→完了を、現行データから正規化する。
実際の状態名と取得方法は最新コードとDBを調べる。推測でAPIやテーブルを新設しない。
演出上の台詞を正式なログや進捗に混ぜない。
「公開できた」「検証完了」は対応するイベントを確認した場合のみ。
処理の成否が不明なら不明と表示。古いイベントが届いても完了を巻き戻さない設計を検討。
演出の片づけを待たせて実際の処理を遅延させない。
APIキー・管理者秘密情報・内部の生ログをキャラ台詞に出さない。

## 動作設計と既知の失敗
最重要: 口パクで全身スプライトを切り替えない。
生成差分は位置や輪郭が少し違い、全身切替で左右にガクガクする不具合をユーザーが確認した。
目・眉・口を独立レイヤーにし、共通の座標・基準点に固定する。
手上げも全身切替は不可。現試作はズレが残るためボタンを無効化。
次の実装では胴体・頭・足を固定し、肩・肘・手首のパーツのみ動かす。
手の上げ下げに加減速・中間姿勢を設け、重複腕や背景の穴を防ぐ。
持ち物は握り位置に追従し、置いてから手を離す。カップだけ浮かせる演出は仮。
歩行は足の接地と移動速度を合わせる。画像を水平移動しただけで歩行完成と呼ばない。
表情候補: 通常、笑顔、大笑い、驚き、きょとん、考え中、困り顔、得意顔、眠そう、安心。
現時点は通常・口開閉・閉眼の試作のみ。位置補正した顔の部分重ねも継ぎ目の目視確認が必要。

## お茶休憩の演出
1. 先輩が画面外へ行き、折り畳みテーブルを持って戻る。
2. テーブルを置き、脚を開いて位置を調整。
3. 後輩が椅子をひとつずつ運び、二人分並べる。
4. 給湯器にカップを置き、ボタンを押し、注ぎ終わるまで待つ。
5. トレーで運び、先輩の前に置いてから自分も座る。
6. 息を吹きかける・ひと口飲む・目を細める・雑談。
7. 案件到着に気づき、カップと家具を片づけ、作業へ切り替える。
小ネタ候補: 椅子をひとつしか持ってこない後輩、黙って自分を指さす先輩。
座る・運ぶ・注ぐ等は専用素材と動作が必要。現時点の6場面は静止画絵コンテであり連続アニメーションではない。

## 次の実装順序
1. 最新ダッシュボードと作業ルールを読む。既存変更を保護。
2. 別ブランチ・独立テストページを作り、既存UIを壊さず編集室とチャットを切り替える。
3. 読み取り専用で実案件の状態を反映。演出から状態変更しない。
4. 動作OFF・履歴閲覧・モバイル・エラー・確認待ちを先に確認。
5. 腕と顔の素材分離、基準点統一、家具の持ち運びなどを仕上げる。
6. 台本と非重複選択を実装し、2時間以上の動作と再読み込みを検証。
7. テストページをユーザーの3モニターで確認し、OK後に本番へ。戻せる変更にする。
