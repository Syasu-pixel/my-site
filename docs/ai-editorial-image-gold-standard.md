# AI編集部 画像ゴールドスタンダード

## 目的
AI編集部の新規記事画像を、従来のChatGPT対話制作で得られていた「見ただけで理解が進む教材画像」の品質へ揃える。

## 正本参照セット
以下の既存採用画像を、本文図解の品質基準として扱う。

`assets/images/star-delta-start-basic/`

1. `star-delta-start-overview.webp`
2. `dol-vs-star-delta-start.webp`
3. `star-delta-switching-sequence.webp`
4. `star-delta-voltage-current-torque.webp`
5. `star-delta-circuit-reading-guide.webp`
6. `star-delta-troubleshooting-guide.webp`

このセットは内容をコピーするためではなく、情報設計・図解密度・視線誘導・親しみやすさ・完成度を比較する基準である。

## このセットに共通する品質
- 一目でテーマが分かる大きな見出し
- 機器、回路、動作、比較対象の主役が明確
- 白背景 + 青系を基本とし、緑・橙・紫・赤を補助色として整理
- アイコン、矢印、番号、囲み、吹き出しを使って読む順番が自然
- 写真風の雰囲気だけでなく、教材として意味を説明している
- 短いラベル中心で、本文の長文をそのまま画像へ貼らない
- 比較画像は左右差・上下差が一目で分かる
- 手順画像はSTEPが視覚的に追える
- 原理画像は流れ・位置・関係が図だけで分かる
- トラブル画像は確認順序が視覚的に分かる
- キャラクターは主役を奪わず、理解を助ける案内役として機能
- 注意事項は色・アイコン・帯で明確に区別
- PCで見栄えし、スマホ縮小でも主題と主要ラベルが残る

## AI編集部での使い方
1. 記事設計時に、各節を `比較 / 原理 / 構造 / 動作 / 手順 / トラブル / 仕様表` へ分類する。
2. `比較 / 原理 / 構造 / 動作 / 手順 / トラブル` は、本文図解候補として必ず検討する。
3. 画像生成前に、その1枚で読者に何を理解させるかを1文で定義する。
4. 実際の画像生成モデルで1枚ずつ生成する。
5. GPTが実画像ピクセルを確認する。
6. 本ゴールドスタンダードと並べ、教材として見劣りしないか比較する。
7. NGなら、同じプロンプトを繰り返さず、情報設計・構図・文字量・視線誘導を変更して再生成する。
8. 採用画像だけをHTMLへ組み込み、Previewでも再監査する。

## 自動不合格の例
- 薄い背景イラストだけで説明力がない
- 装置を1つ置いただけで原理・違いが分からない
- 長い本文を画像内に貼っただけ
- 白いカード + 箱 + 矢印だけで、既存採用画像より明らかに簡素
- 比較節なのに、違いが視覚化されていない
- 手順節なのに、順番を目で追えない
- トラブル節なのに、切り分け順が分からない
- PCでは読めるがスマホ縮小で主要ラベルが消える
- キャラクターが別人、または主役になりすぎる
- 画像として綺麗でも、本文理解がほとんど進まない

## 画像単体の合格質問
IMAGE REVIEWERは各画像に対して次を確認する。

- この画像だけ見て、節の主題が10秒以内に分かるか。
- 本文を読む前より理解が進むか。
- 比較なら違い、手順なら順番、原理なら関係、トラブルなら確認順が目で分かるか。
- 文字がなくても主図の意味が概ね伝わるか。
- 文字は補助説明として大きく読みやすいか。
- ゴールドスタンダード6枚と並べて、明らかに簡素・薄い・広告風になっていないか。
- スマホで縮小しても主要要素が残るか。

1つでも重大なNGがあれば再生成する。

## 記事全体の合格質問
- 文章と表ばかりになっていないか。
- 初心者がつまずく主要概念に図解があるか。
- 図解が本文の重複ではなく、理解を短縮しているか。
- 画像セット全体で色・線・人物・トーンが統一されているか。
- heroだけ高品質で本文画像が弱い状態になっていないか。

新規初心者向け記事では、本文主要図解を原則2〜5枚候補設計し、不要なら理由を記録する。
