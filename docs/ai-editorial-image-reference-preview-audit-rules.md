# AI編集部 画像参照・Preview監査ルール v1

## 1. 目的
画像生成のたびに正本参照を必須化し、キャラクター同一性・機器配置・図解の現実性を担保する。また、管理者が大量のスクリーンショットを手作業で共有しなくても、GPTがPreviewを直接または自動取得した画面証跡から監査できる運用を標準化する。

## 2. 画像ごとの必須参照セット
AI画像を1枚生成するたびに、生成前に次を確認する。記事単位で1回だけ確認して済ませてはならない。

1. `docs/image-generation-rules.md`
2. `docs/ai-editorial-article-image-strict-rules.md`
3. `docs/ai-editorial-image-gold-standard.md`
4. 正本キャラクターテンプレート `assets/images/character-templates/senpai-kouhai-character-template.png`
5. 用途に合うスター・デルタ採用画像
6. 当該画像専用の図解設計書（目的、構図、機器位置、矢印方向、必須ラベル、禁止事項）
7. 記事で使用する公式一次資料のうち、その画像の内容に関係する箇所

参照できないものがある場合は、参照したふりをせず未確認として止める。

## 3. キャラクター同一性は必須品質条件
- キャラクターを含む画像は、毎回、正本テンプレートそのものを画像参照として生成・監査工程へ渡す。
- 「白ヘルメットの男性」「青ヘルメットの女性」など文章だけの特徴指定で代替しない。
- 採用済みheroだけを参照して正本テンプレート参照を省略しない。
- 先輩・後輩は別画像でも同一人物に見えなければならない。
- 顔立ち、髪型、頭身、服装、ヘルメット、年齢感、線のタッチ、表情トーンの大きなずれは致命的不合格とする。
- `似た雰囲気`、`同じ職種に見える` 程度では合格にしない。
- キャラクターが正本とずれている場合、他の品質が95点以上でも採用しない。
- 上級記事ではキャラクターを減らすが、使う場合の同一性条件は緩和しない。

## 4. ゴールドスタンダードは実画像として参照する
品質基準は説明文だけでなく、次の実画像そのものを参照する。

`assets/images/star-delta-start-basic/`
- `star-delta-start-overview.webp`
- `dol-vs-star-delta-start.webp`
- `star-delta-switching-sequence.webp`
- `star-delta-voltage-current-torque.webp`
- `star-delta-circuit-reading-guide.webp`
- `star-delta-troubleshooting-guide.webp`

用途ごとの近い見本を優先する。
- overview → `star-delta-start-overview.webp`
- comparison → `dol-vs-star-delta-start.webp`
- process / sequence → `star-delta-switching-sequence.webp`
- mechanism / numerical relationship → `star-delta-voltage-current-torque.webp`
- reading guide → `star-delta-circuit-reading-guide.webp`
- troubleshooting → `star-delta-troubleshooting-guide.webp`

ゴールドスタンダードは見た目の飾りではなく、情報階層、色分け、視線誘導、図解密度、キャラクター品質の基準とする。

## 5. 機器配置・方向・動作の現実性監査
図解は、装置の形がそれらしいだけでは不十分。実務上の位置関係・向き・動作が正しく見えることを必須とする。

画像生成前の図解設計書に最低限、次を記録する。
- 主役機器
- 機器の設置位置
- 機器の向き
- 相手機器との位置関係
- ワークまたは信号の進行方向
- 矢印の始点・終点・意味
- 正常状態と異常状態の違い
- 描いてはいけない配置

IMAGE REVIEWERは `technical truth` と `visual truth` を分けずに確認する。機器配置や矢印が現実と異なる場合は不合格。

### 対向型・多光軸エリアセンサの基準例
- 投光器と受光器は基本的に搬送路・検出領域の左右へ対向して縦置きする。
- 複数の光軸が投光側から受光側へ横切る。
- ワークは投光器と受光器の間を通過する。
- センサ本体をコンベア搬送面の上へ寝かせて置いた図を基本配置として使わない。
- 光軸、検出幅、検出距離の矢印は互いの意味が混ざらないようにする。
- 安全ライトカーテンとして認証されていない汎用エリアセンサを、安全機器として描かない。

## 6. 記事固有用語の定義を画像にも反映する
- メーカーが対象製品を `エリアセンサ` と呼ぶ場合、そのメーカー用語を尊重する。
- 一般名称に複数の現場用法がある場合、記事冒頭で `この記事で扱う〇〇` を定義する。
- 今回のような対向型・多光軸エリアセンサと、AGV等で用いられる走査型・回転型の距離センサ/スキャナを同一物として描かない。
- `ライトカーテン` と呼ばれることがある外観でも、安全用途かどうかは製品カテゴリ・認証・公式資料で分ける。

## 7. 画像生成前チェックポイント
各画像について、生成直前に内部記録として次を持つ。

- `purpose`
- `article_level`
- `character_template_checked`
- `gold_reference_files`
- `official_source_refs`
- `equipment_layout`
- `flow_direction`
- `mandatory_labels`
- `forbidden_layouts`
- `character_required`

`character_required=true` なのに `character_template_checked=false` の場合は生成禁止。

## 8. 画像レビューの不合格条件
次のいずれかは点数に関係なく不合格。
- キャラクターが正本と別人に見える
- 機器の置き方・方向が現実と異なる
- 矢印の順序・接続が破綻している
- 主題と無関係な機器が追加されている
- 安全用途と汎用用途を混同している
- 技術的に誤読を誘う
- スター・デルタ採用画像と比較して情報設計が明確に弱い

## 9. 本文可読性
Previewでは画像だけでなく、本文の読み飛ばしやすさも監査する。
- 連続する黒文字段落を長くしすぎない。
- 重要語・結論・注意は、既存サイトのデザインシステム内で太字、アクセント色、要点ボックス、短い箇条書き等を使い分ける。
- 色は飾りではなく情報階層に使う。
- 1節に長文が続く場合は、要点カード・箇条書き・図解への分割を検討する。
- `文章量が多い = 詳しい` と評価しない。読者が途中で読むのを諦めない密度を優先する。

## 10. 参照日時は絶対日付
- `先月`、`昨日`、`約2週間前` 等の相対表現を記事の参照記録に使わない。
- 検索・クロール・確認日時を表示する必要がある場合は `YYYY年M月D日確認` の絶対日付とする。
- 検索エンジンの表示するクロール時点を、資料の公開日・改訂日として扱わない。
- 公開日/改訂日を確認できない場合は `確認できない` とする。

## 11. GPT Preview監査を管理者スクショ依存にしない
Preview完成後、GPT監査は管理者が大量のスクリーンショットを撮ることを前提にしない。

標準経路:
1. Preview URLを案件成果物に保存する。
2. GPT監査へPreview URLを直接渡す。
3. GPTが直接閲覧可能な環境では、PC幅とモバイル幅でページ全体を確認する。
4. 直接閲覧できない実行環境では、自動ブラウザでPreviewを開き、PC全ページ画像とモバイル全ページ画像を自動取得してGPTへ渡す。
5. GPTは画面証跡とHTMLソースの両方を監査する。
6. 明確なNGがあれば管理者確認へ上げる前に同じ案件へ修正を戻す。

管理者は必要に応じて追加スクリーンショットを提示できるが、それを通常運用の必須作業にしない。

## 12. Preview監査対象
GPTは最低限、次を確認する。
- heroの見え方
- 本文の黒文字密度、読み飛ばしやすさ
- 要点の色分け・強調
- 本文図解の品質
- キャラクター同一性
- 機器配置・矢印・順序
- 右サイドバーの内容が記事テーマと一致しているか
- 表の横幅・モバイル可読性
- 公式資料リンクと日付表記
- 会話UI
- 寄付導線
- フッター
- PC/モバイル崩れ

## 13. HUMAN GATEへの条件
次をすべて満たすまで `NEEDS_HUMAN` にしない。
- HTMLソース監査完了
- 生成画像の実画像監査完了
- 正本キャラクターテンプレート比較完了（キャラ使用時）
- 機器配置・矢印監査完了
- GPT Preview監査完了
- PC/モバイルの視覚監査完了

自動ブラウザやGPT Preview監査経路が一時的に利用不能な場合は、その事実を明示して `Preview視覚監査未完了` とする。管理者へスクリーンショット大量取得を暗黙に押し付けない。
