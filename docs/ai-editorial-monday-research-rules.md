# Denkicontrol AI編集部 月曜定例・調査企画ルール v1

## 1. 位置づけ
この文書は、`docs/ai-editorial-weekly-routine.md` の「月曜日 — 調査・企画」を具体化する補強ルールである。月曜定例に関して本書と曜日別ルーティンの記述が競合する場合は、本書のより具体的な条件を優先する。

月曜の目的は「記事を作ること」ではなく、火〜日に何を作る・直す・つなぐべきかを、サイト実データと技術一次情報に基づいて決めることである。

## 2. 月曜定例の必須入力
月曜調査では、取得可能な範囲で次を確認する。

### A. Search Console実データ
接続済みのGoogle Search Consoleを優先し、Web検索だけで代替しない。
最低限、次を確認する。
- クリック数
- 表示回数
- CTR
- 平均掲載順位
- 検索クエリ
- 流入ページ
- 直近28日と、その前28日の比較
- 可能なら直近7日と前7日の変化

特に次を抽出する。
- 表示回数は多いがCTRが低いページ
- 平均順位4〜10位で伸ばせるページ
- 平均順位11〜20位で追加記事・内部リンク・更新の効果が見込めるページ
- クリック・表示回数が急伸しているテーマ
- クリック・表示回数・順位が明確に下落しているページ
- 複数URLが同一または近いクエリで競合している可能性

Search Consoleへ接続できない場合は、その事実を明記し、検索需要・SEO効果を「定量評価済み」と扱わない。公開Web検索だけで検索実績を断定しない。

## 3. サイト全体・GitHub監査
Search Consoleだけで企画を決めない。GitHub mainと公開サイトの両方を確認し、次を整理する。
- 記事一覧
- カテゴリ構成
- 初級 / 中級 / 上級の充足度
- 同一テーマの記事群
- 重複・カニバリ候補
- 孤立記事候補
- ハブ不足
- 関連記事・学習順序の不足
- 既存記事から次段階へ進めないテーマ
- 公開ページとGitHubの不整合

「サイト全体を確認した」と記録する場合は、調査対象範囲・対象URL群・カテゴリ・確認方法を内部記録する。数ページだけ確認してサイト全体監査済みと表現しない。

## 4. 初級・中級・上級の配分判定
新規記事候補は初心者向けに固定しない。

月曜レポートでは主要テーマごとに、少なくとも次を判定する。
- beginner coverage: sufficient / partial / missing
- intermediate coverage: sufficient / partial / missing
- advanced coverage: sufficient / partial / missing

判断原則:
- 初級が十分なら、同じ基礎用語の言い換え記事を増やさない。
- 初級が十分で中級が薄いテーマは、中級を優先する。
- 初級・中級が揃っているテーマは、検索需要・読者価値・事業価値があれば上級候補を出す。
- 上級記事は前提記事への内部リンクを必須候補として設計する。

週次企画には、必要に応じて「今週の推奨レベル配分」を記載する。例: beginner 0 / intermediate 2 / advanced 1。

## 5. 新規記事候補の評価項目
各候補はタイトルだけ並べず、次を記録する。
- article_level: beginner / intermediate / advanced
- 想定検索意図
- 対象読者
- 解決する実務課題
- 既存記事との差分
- 既存初級記事との接続
- 前提記事
- 内部リンク元候補
- 内部リンク先候補
- 必要な公式一次資料
- 必要な図解の種類
- 安全・機種依存上の注意
- GSC根拠
- 期待効果
- 重要度
- 緊急度

## 6. 更新候補の評価
既存記事の更新候補では、次を確認する。
- GSCで順位・CTR・クリックが落ちていないか
- 検索意図とのずれ
- 初級向けの説明不足ではなく、中級への発展不足になっていないか
- メーカー公式資料の改訂
- 廃番・後継機
- 仕様変更
- 安全情報の追加・変更
- 公式URL切れ
- 図解不足
- 関連記事への導線不足

公開日・更新日・改訂日を確認できない場合は推測しない。

## 7. メーカー公式資料の確認
型式・仕様・パラメータ・規格・安全・設定・配線・通信・アラーム等が関わる候補では、企画段階でも主要一次情報の有無を確認する。

記録項目:
- メーカー
- 資料名
- 対象機種 / シリーズ
- 公開日または改訂情報
- URL
- その資料で確認できること
- 確認できないこと

日本語記事では日本語公式資料を最優先する。

## 8. 優先順位の決め方
「効果が高そう」だけで順位付けしない。

少なくとも次の軸で評価する。
- GSC検索機会
- 読者課題の強さ
- 既存記事との重複の少なさ
- 中級・上級へのサイト成長効果
- 内部リンク・ハブ効果
- 技術一次情報の確実性
- 安全上の重要度
- 制作コスト
- 事業・問い合わせ・収益への寄与可能性

GSC未取得の場合、GSC検索機会は `unknown` とし、総合順位に不確実性を明示する。

## 9. 月曜成果物の必須セクション
月曜レポートは最低限、次の順でまとめる。
1. 今週の結論
2. GSCサマリー
3. サイト・記事カバレッジ
4. 初級 / 中級 / 上級の不足
5. 新規記事候補
6. 更新候補
7. 内部リンク・ハブ改善候補
8. メーカー公式資料の更新・確認事項
9. 今週の推奨レベル配分
10. 優先順位一覧
11. 未確認事項 / 不確実性

候補は複数出してよいが、月曜調査から新しい制作案件を自動生成しない。

## 10. 禁止事項
- GSC未取得なのに検索実績に基づく順位だと断定する。
- Google検索結果のクロール日を記事の公開日・改訂日として扱う。
- 数ページ確認しただけで「全記事監査済み」とする。
- 初心者向け記事を増やすことをデフォルトにする。
- 既存初級記事が十分なのに同じ用語の言い換え記事を上位候補にする。
- メーカー・型式未確認のまま端子番号・パラメータ・安全機能を企画へ固定する。
- 月曜候補を管理者の制作指示なしで火曜以降の新規キューへ自動展開する。

## 11. 月曜テンプレート推奨文
「月曜の定例を開始。接続済みGoogle Search Consoleの実データ、GitHub main、公開サイト、既存記事、カテゴリ、内部リンク、メーカー公式一次資料を確認してください。GSCではクリック・表示回数・CTR・平均順位・クエリ・ページ・前期間比を確認し、4〜10位、11〜20位、CTR低下、急伸、急落、カニバリ候補を抽出してください。サイト側では初級・中級・上級の充足度をテーマ別に判定し、初級が十分な領域では中級を優先、前提が揃った領域では上級も候補化してください。新規記事、更新、内部リンク・ハブ改善をGSC根拠、読者価値、既存記事との差分、一次資料の確実性、安全性、事業効果で順位付けしてください。GSC等の取得不能項目は推測せず未確認と明記してください。今回は調査・企画を1成果物としてまとめ、見つけた候補から制作案件を自動生成しないでください。」
