# AI編集部 プロジェクト状態

## 現在の状態: 一時閉鎖（TEMPORARILY CLOSED）

**決定日: 2026-09-09**

AI編集部は解体・削除しない。ただし、現在はプロジェクトを**一時閉鎖**とする。

この状態ファイルは、AI編集部の運用可否に関して `docs/ai-editorial-master-rules.md`、`docs/ai-editorial-weekly-routine.md` その他のAI編集部関連文書より優先する。再開決定が明示されるまでは、既存の週次ルール・自動制作ルールを実運用しない。

## 閉鎖中のルール

- 新規のAI編集部案件を開始しない。
- 月〜日の定例AI編集部運用を停止する。
- OpenAI / Gemini 等を使う自動記事生成、画像生成、AI監査、再生成ループを実行しない。
- AI編集部を理由とする新規のAPI消費を発生させない。
- 既存コード、Supabase Edge Functions、GitHub履歴、ドキュメント、ダッシュボード、過去の案件ログは削除せず保存する。
- AI編集部の解体や全面削除は行わない。
- 保守上必要な重大セキュリティ修正を除き、閉鎖中はAI編集部の機能追加・改善開発を原則停止する。
- 再開前に、古いモデル名・API仕様・Cloudflare/Supabase/GitHub構成をそのまま信用せず、現行仕様を再監査する。

## 閉鎖中の代替運用: ChatGPTが週次役割を引き継ぐ

AI編集部そのものは停止するが、これまで月〜日に割り当てていた**サイト成長の役割は廃止しない**。AI編集部再開までは、通常のChatGPTチャットを実行主体として引き継ぐ。

標準の役割分担は以下とする。

- **月曜: 調査・企画** — サイト全体、既存記事、カテゴリ、検索状況を確認し、新記事候補・更新候補・内部リンク不足を優先順位付きで整理する。
- **火曜: 新記事制作** — 公式資料を優先して調査し、新記事の構成、本文、必要画像、GitHub反映、PR確認まで進める。
- **水曜: 既存記事改善** — 古い技術情報、説明不足、検索意図とのずれ、初心者が理解しにくい箇所を改善する。
- **木曜: 導線改善** — トップ、カテゴリ、関連記事、内部リンク、学習順序を見直し、回遊しやすい構造へ改善する。
- **金曜: SEO・検索確認** — Search Console等の実データを使い、表示回数、クリック、順位、インデックス状態、伸びている記事、改善候補を確認する。
- **土曜: UX・画像品質** — スマートフォン表示、読みやすさ、画像、図解、カード、ナビゲーション、レイアウト崩れを確認・改善する。
- **日曜: 週次まとめ** — 今週の成果、未解決事項、次週の優先順位を整理する。

### ChatGPT運用ルール

- 曜日ルールは**自動実行スケジュールではなく、作業テンプレート**として扱う。
- 管理者が「火曜やって」「今週分まとめて」「月〜水まで進めて」などと指示した場合、ChatGPTは該当役割をまとめて実行してよい。
- GitHub上の調査、実装、PR作成、差分確認、問題のないPRのマージ、必要な再確認は、管理者の都度確認を減らすため可能な範囲で連続して進める。
- サイト方針を大きく変える変更、公開内容の意味を大きく変える変更、大きな課金・外部サービス設定変更は管理者判断を優先する。
- AI編集部の自動オーケストレーターやAPI再生成ループを使わず、通常のChatGPT会話と利用可能なGitHub / Search Console / Web等のツールで実施する。
- この代替運用はAI編集部の再開を意味しない。AI編集部本体は引き続き一時閉鎖状態とする。

## 再評価の目安

**約6か月後、またはAI/APIの能力・価格・安定性に大きな改善があった時点**で再評価する。

再評価では最低限、以下を確認する。

1. 記事本文を人間の細かな介入なしで安定して完成できるか。
2. 技術図解・OGP・hero画像を、許容コスト内で安定生成できるか。
3. 1記事あたりのAPI費用が実運用に見合うか。
4. Previewまで途中停止せず自走できるか。
5. 管理者の確認を最終1回程度に抑えられるか。
6. 現行のChatGPT単体運用と比べて、AI編集部を採用する明確なメリットがあるか。

上記を検証したうえで、**AI編集部を再採用する / 設計を変更して再開する / 閉鎖を継続する**のいずれかを管理者が判断する。

## 再開条件

AI編集部は、管理者が明示的に「再開」と決定するまで運用再開しない。

単にコードが残っていること、API残高があること、モデルが更新されたこと、ダッシュボードを開いたことだけでは再開扱いにしない。
