# Denkicontrol 四コマ漫画 制作チェックリスト

更新日: 2026-10-06  
状態: 条件付き制作ルール

## 1. 制作前
- [ ] 対象記事を1本決めた
- [ ] 対象記事が最新mainの内容である
- [ ] 元記事の技術内容を読んだ
- [ ] 必要な `docs/reference-notes/{slug}.md` を確認した
- [ ] `docs/comic-style-guide.md` を確認した
- [ ] `docs/comic-character-sheet.md` を確認した
- [ ] `assets/images/comic-character-anchors/yonkoma-chibi-senpai-kouhai-anchor-01.png` を実際に開いて、先輩・後輩の見た目を目視確認した
- [ ] `docs/image-generation-rules.md` の関連キャラクタールールも確認した
- [ ] 四コマで伝えるテーマを1つに絞った

## 2. 台本
- [ ] 4コマで1つの疑問・気づきに収まっている
- [ ] 1コマ1メッセージになっている
- [ ] 後輩の疑問が読者視点として自然
- [ ] 先輩の説明が長すぎない
- [ ] 元記事と矛盾しない
- [ ] 機種依存・安全条件を一般化していない
- [ ] 最終コマまたは投稿文に記事CTAがある

## 3. 画像生成
- [ ] 出力キャンバスが **正方形 1:1** である（原則 1254×1254 相当）
- [ ] 3:4 / 4:5 / 縦長ポスター / 横長スライドへ勝手に変わっていない
- [ ] 上部タイトル帯 → 2×2四コマ → 下部CTA帯のシリーズ構造を維持している
- [ ] `assets/images/comic-character-anchors/yonkoma-chibi-senpai-kouhai-anchor-01.png` を最優先アンカーとして参照した
- [ ] 通常記事用 character template は補助参照に留め、四コマ用正本と競合させていない
- [ ] 正式採用済みパイロット `assets/images/comics/sensor-basic/sensor-basic-yonkoma-01-pilot.png` を実際に開いて第二アンカーとして参照した
- [ ] 先輩・後輩が別人化していない
- [ ] **後輩＝疑問・気づき、先輩＝説明・整理**の役割が入れ替わっていない
- [ ] 後輩が後輩へ教える、先輩が後輩役になる、同じ役割の人物が重複する構図になっていない
- [ ] ヘルメット色・服装・髪型・年齢感が一致している
- [ ] 青系のシリーズ世界観を維持している
- [ ] スマホで読める文字サイズ
- [ ] 吹き出しが人物・機器・重要図を隠していない
- [ ] 技術機器の形・位置・方向に誤解がない
- [ ] 実在メーカーのロゴ・UI・銘板を不要に再現していない

## 4. 技術レビュー
- [ ] 元記事の要点と一致
- [ ] reference note の「断定しない範囲」に違反していない
- [ ] 危険作業を促していない
- [ ] 安全機器と一般機器を混同していない
- [ ] 配線・信号・機械構造・搬送方向に物理矛盾がない
- [ ] 四コマだけで実作業手順を完結させていない

## 5. シリーズ統一レビュー
- [ ] 既存の採用四コマと並べても同シリーズに見える
- [ ] キャンバス比率が1:1で、直近採用作と縦横比・余白感が一致している
- [ ] タイトル帯・2×2枠・CTA帯の高さ比率が大きくズレていない
- [ ] 各コマで先輩・後輩の役割関係が正しい
- [ ] キャラ一致
- [ ] 色味一致
- [ ] 線・背景密度一致
- [ ] セリフの人格一致
- [ ] CTA表現が大きくぶれていない

## 6. 正式採用前
- [ ] ユーザーが画像を目視確認した
- [ ] 元記事URLが正しい
- [ ] 投稿文と漫画の内容が一致
- [ ] SNS用画像の比率・可読性を確認
- [ ] 必要な商用・著作権・メーカー表記上の問題がない
- [ ] 採用画像の保存先・ファイル名を記録した

## 7. 正式採用後の必須パイプライン

ユーザーが「正式採用」「採用で進める」等を明示したら、画像生成だけで完了扱いにしない。以下を原則1セットで完了する。

### 7-1. 採用原本を固定
- [ ] 最終承認された画像そのものを採用原本として固定した
- [ ] 画像生成ID、元ファイル名、byte size、SHA-256、GitHub配置先を記録した
- [ ] 採用後の保存都合だけで再生成・再描画していない
- [ ] 採用画像のGitHub配置は `docs/adopted-image-github-placement-rule.md` の検証付きバイナリ転送だけを使った
- [ ] `main` へ画像バイナリを直接転送していない
- [ ] 転送完了後、一時依頼JSONが削除され、目的パスに画像が存在することを確認した
- [ ] 可能な場合は元ファイルとGitHub保存後のGit blob SHAまで照合した

### 7-2. 採用記録・バックログ
- [ ] `docs/comic-scripts/{slug}-yonkoma-01.md` を新規作成または更新し、状態を **正式採用済み** にした
- [ ] 元記事、reference note、採用画像パス、採用内容、技術ガード、シリーズ参照を記録した
- [ ] 新規comic scriptは `docs/rules/catalog.json` と生成対象の `docs/rules/index.md` へ登録した
- [ ] バックログへ「四コマ追従完了」を記録し、後から未対応扱いに戻らないようにした

### 7-3. トップページ4コマ導線
- [ ] `index.html` の「4コマでわかる電気制御」へ正式採用画像を1作品追加した
- [ ] リンク先は元記事URLと一致している
- [ ] alt、表示タイトルが漫画内容と一致している
- [ ] 通常表示・拡大表示の両方で新作品が切り替え対象になることを確認した
- [ ] 初期表示用の静的カウンター値が現在の作品数と一致している
- [ ] 作品数が増えても、1枚描画方式・自動送り・手動送りを維持し、縦積みtrack方式へ戻していない
- [ ] `index.html` 更新に伴う additional shell baseline / site inventory 等、既存の検査正本を正規手順で同期した

### 7-4. GitHub本番反映
- [ ] 最新 `main` から作ったPreview/公開ブランチで差分を管理した
- [ ] Rule catalog / Additional page shared shells / GitHub Pages 等、変更に関係する検査結果を確認した
- [ ] 失敗が出た場合は「今回変更による失敗」か「既存・無関係の失敗」かをログで切り分けた
- [ ] 採用内容と必要な検査正本だけを本番PRへ含め、Preview専用ファイルを混ぜていない
- [ ] 本番マージ後、`main` 上で採用画像・comic script・トップページ導線が存在することを再確認した

### 7-5. Instagram投稿予約
- [ ] 投稿前にMetricoolの既存予約を取得し、日時の重複・順序を確認した
- [ ] ユーザー指定日時がある場合はそれを優先し、指定がない場合は既存の投稿順を崩さない次の空き枠へ予約した
- [ ] 投稿画像はGitHubへ保存した正式採用原本と同じ版を使用した
- [ ] 投稿文は漫画の内容と元記事に一致し、プロフィールのリンクから記事へ誘導する
- [ ] InstagramのAI生成コンテンツ申告を必要に応じて有効にした
- [ ] 予約後、対象投稿が `PENDING` かつ `draft:false` であることを再取得して確認した

### 7-6. 採用取り消し・画像不備時
正式採用後にキャラクター崩れ、技術誤り、文字崩れ等が判明した場合は放置しない。

- [ ] comic scriptを **要修正・再制作バックログ** 等へ戻す
- [ ] バックログへ修正待ちを記録する
- [ ] トップページの4コマ表示対象から一時除外する
- [ ] Instagram予約済みなら、公開前にドラフト化して自動投稿を止める
- [ ] 修正版を再度ユーザー確認し、正式採用後にこの7章の工程をやり直す

**完了条件:** 「画像を採用した」だけでは完了ではない。画像保存、採用記録、バックログ、トップページ導線、GitHub本番反映、Instagram予約確認まで完了して初めて、その四コマ回をクローズする。

## 8. 初回パイロット
シリーズ1本目は通常作品ではなく、世界観を固定するパイロットとして扱う。

採用後に固定する:
- キャラクター外観
- 配色
- 線のタッチ
- コマ枠
- 吹き出し
- フォント/文字密度
- CTA位置
- サイト名表示
- 背景密度

正式採用パイロット:
- `assets/images/comics/sensor-basic/sensor-basic-yonkoma-01-pilot.png`

量産は、この正本画像を基準にユーザー承認済みの世界観を維持して開始する。
