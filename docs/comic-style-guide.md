# Denkicontrol 四コマ漫画スタイルガイド

更新日: 2026-09-25  
状態: 条件付き制作ルール

## 1. 適用範囲
Denkicontrol の記事を元に、SNS・記事導線用の四コマ漫画を制作・更新するときに適用する。

四コマ漫画は記事本文の代替ではなく、**記事への入口となる再利用コンテンツ**として扱う。

## 2. 世界観
- 「やさしい技術解説漫画」を基本とする。
- 清潔感、親しみやすさ、実務感を両立する。
- 青系を基調に、白・グレーをベースとする。
- 実写風・劇画調・子ども向けすぎる表現・過度な萌え表現へ寄せない。
- シリーズを通して線の太さ、色味、背景密度、キャラクターの雰囲気を大きく変えない。

## 3. キャラクター
- 基本キャラは既存の先輩・後輩の2人。
- 画像生成の正本は `assets/images/character-templates/senpai-kouhai-character-template.png`。
- HTML会話用の `assets/images/guide-characters/` は画像生成正本として使わない。
- 詳細な固定条件は `docs/comic-character-sheet.md` に従う。
- 新しい別キャラを勝手に作らない。

## 4. 四コマ構成
原則:
1. 疑問・現場の困りごと
2. 状況整理・ありがちな勘違い
3. 先輩の要点整理
4. 理解・まとめ・記事へのCTA

1コマ1メッセージを基本とし、技術説明を詰め込みすぎない。

## 5. セリフ
- 先輩: 落ち着いた説明役。上から目線にしない。
- 後輩: 読者の疑問・気づきを代弁する。
- 短く、読みやすく、専門用語を詰め込みすぎない。
- 危険作業や機種依存条件を軽く断定しない。

## 6. 技術品質
- 元記事と `docs/reference-notes/{slug}.md` を確認する。
- reference note が必要な記事で未作成なら、四コマ制作より先に補完する。
- メーカー仕様・安全条件・機種依存事項を漫画向けに単純化しすぎない。
- 四コマ内で詳細手順を完結させず、詳細は元記事へ誘導する。
- 技術的に誤解を与える構図・配線・機器配置は不採用。

## 7. レイアウト
- 原則4コマ。
- SNSでスマホ閲覧される前提で文字を大きくする。
- 毎回レイアウトを大幅に変えず、シリーズとして同じ作品に見えることを優先する。
- CTA位置、タイトル位置、サイト名表示はパイロット版確定後に固定する。

## 8. CTA
最終コマまたは投稿文から必ず元記事へ誘導する。

例:
- 続きは Denkicontrol.com で
- 詳しくは「○○」の記事で
- 記事で確認ポイントを整理しています

## 9. 正本と変更管理
四コマの統一感は次を正本として維持する。
1. 本ファイル
2. `docs/comic-character-sheet.md`
3. `docs/comic-production-checklist.md`
4. 画像生成正本キャラクターテンプレート
5. ユーザー承認後の最初のパイロット四コマ

パイロット採用後は、後続作品のキャラクター、配色、線、吹き出し、余白、CTAの第二アンカーとして扱う。

世界観を変える場合は、先に本ガイドを更新してから次作品へ反映する。
