# Reference Notes

このフォルダは、記事ごとの公式参照元・確認対象マニュアル・記事で使う範囲・断定しない範囲・画像ルールを記録するためのメモ置き場です。

## 目的

- 記事本文の根拠を後から確認できるようにする。
- メーカー公式資料を確認した範囲と、断定しない範囲を分ける。
- ChatGPT / Codex が次回以降の記事作成・修正時に同じ参照方針を再利用できるようにする。
- 取扱説明書PDF本体は原則としてGitHubに保存せず、公式URL・公式マニュアル名・確認日・使用範囲を記録する。

## ファイル名

記事スラッグに合わせる。

例:
- got-touch-panel-basic.md
- servo-motor-basic.md
- inverter-basic.md

## 現場知識採否の記録テンプレート（記事別）

新規記事・実質更新で現場知識を検討した場合、対象slugの参照メモに以下を追記する（該当なしなら省略理由を作業ログへ記す）。

```text
### 現場知識の採否
- 台帳ID／分野：
- 読者の疑問と既存記事の説明状況：
- 現場の呼称／正式な名称／使われる範囲：
- 出典URL／取得・再確認日／公開範囲：
- 出典属性：メーカー一次資料／業界団体／実務企業／個人の経験談／編集用仮説
- メーカー公式資料URL／公式資料確認日／型式・条件：
- 独立照合と矛盾・未確認事項：
- 安全上の前提・一般化できない内容：
- 判定：A（検討可）／B（追加検証）／C（見送り）
- 最終判断：採用／一部採用／見送り と理由：
- 記事に反映した箇所／変更前との違い：
```

台帳のA判定は原稿への自動採用を意味しない。情報不足ならB、危険・不正確・主題から外れるならCとする。原典の長文・写真・図版を複製しない。

## 現場由来の知見を記事へ取り入れる場合（2026-11-07追補）

現場での呼び方、工具の使い分け、故障時の考え方、保守性の判断を扱う際は、[サイト方針の現場知識一覧](../denkicontrol-site-strategy.md#16-現場知識の蓄積と差別化2026-11-07-追補) を確認する。横断一覧は取材・検討候補であり、それだけで実際の経験や技術的事実が確認されたことにはならない。

記事に使う項目は本ファイル群の対象slugに追記し、少なくとも次を区別して残す。

- 正式名称と現場呼称（どのような設備・場面で使うか、意味の揺れ）
- メーカー一次資料の根拠と確認日
- 実体験として確認できた情報か、編集上の説明例・未確認候補か
- 判断の考え方と、その方法が通用しない条件・安全上の前提
- 記事に採用する内容、掲載を見送った内容と理由

現場経験をAIが捏造しないこと。現場名、顧客名、設備固有の回路やプログラム等の機密情報を公開資料に含めないこと。本文で「現場では必ず」と断定せず、公式資料・設備仕様を優先すること。
