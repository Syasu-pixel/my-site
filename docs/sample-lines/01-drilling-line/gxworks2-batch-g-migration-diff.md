# 01 Drilling Line — GX Works2 Batch G 移行差分

Status: Active / Section 15～16 GX Works2移行用

## 1. 対象

- Section 15 `PRODUCTION_TAKT`
- Section 16 `MAINTENANCE`
- ターゲット：`FX3U-80MT/DS + FX2N-16EX`
- エンジニアリング：GX Works2

既存のGX Works3設計ロジックを正として、FX3U/GX Works2で再確認が必要な差分だけを管理する。

## 2. そのまま流用する設計思想

以下はGX Works2版でも維持する。

- D200：総投入数
- D201：総排出数
- D202/D203：OK/NG予約。品質判定未実装のため自動加算しない
- D210：直近サイクル
- D211：平均
- D212：最大
- D213：最小
- D120：目標タクト
- D300～D305：運転時間系
- D310～D319：ST/CY動作回数
- D330～D351：異常発生回数
- D360～D365：診断/復旧統計
- 同一イベントを毎スキャン加算しない
- アラーム回数はOFF→ON新規発生で1回だけ加算
- 主軸運転時間は要求ではなくM166 RUN FB基準
- RESET PBで生産数・保守統計を消さない
- Section 16からY、M305、M321、安全監視、アラームRESETを操作しない

## 3. Section 15 — Production/Takt

### 3.1 D200 投入数

GX Works2でも次の条件を維持する。

```text
M323 投入可
AND M184 投入完了PB立上り
AND M116 CV01在荷確認
→ accepted-load-event
→ D200 +1
```

PB単独では加算しない。

GX Works2差分：

- accepted-load-eventの1スキャン化命令/補助Mを正式決定する。
- 未登録Mを勝手に消費しない。

### 3.2 D201 排出数

```text
M515工程経由
AND M209 排出通過COMPLETE
AND M140 OFF
AND M516→M517完了イベント
→ D201 +1
```

M517が複数スキャン成立しても1回だけ加算する。

### 3.3 D202 / D203

GX Works2版でも予約のまま。

禁止：

- D201をD202へコピー
- 「異常なし」をOK判定にする

### 3.4 サイクル計測

一次基準は維持する。

- START：M500→M501遷移イベント
- END：M517完了イベント

GX Works2差分：

- FX3Uで採用する実時間計測方式を正式化する。
- Tデバイス、特殊リレー/レジスタ、カウンタ方式のどれを使うかはプロジェクト上で確認する。
- D210/D120の内部単位を同一にする。
- 秒/100ms等の換算を未確認のまま固定しない。

### 3.5 D212 最大 / D213 最小

ロジックはそのまま。

```text
D210 > D212 → D212 = D210
```

D213は初回有効サイクルを別扱いし、初期0のまま固定されないようにする。

### 3.6 D211 平均

概念は維持する。

```text
TOTAL_CYCLE_TIME += D210
VALID_CYCLE_COUNT += 1
D211 = TOTAL_CYCLE_TIME / VALID_CYCLE_COUNT
```

GX Works2差分：

- FX3Uでの32bit加算/除算命令を正式確認
- 累積時間・有効件数用Dを正式割付
- 16bitで足りない累積値を無理に単独Dへ入れない

### 3.7 M774 タクト超過

```text
D210 > D120 → M774
```

警告であり、単独でM305を停止しない。

## 4. 異常/通常停止サイクル

GX Works2版でも以下を維持する。

- M324で中断した未完サイクルを正常統計へ入れない。
- M517まで到達しないサイクルは有効件数に含めない。
- 通常STOP中の時間をD210へ含めるかは最終仕様TBD。

教材一次案は「実サイクル時間として通常停止時間を含める」だが、GX Simulator2で挙動確認後に固定する。

## 5. Section 16 — Maintenance

### 5.1 D300～D305 運転時間

既存割付を維持する。

- D300 CV01
- D301 CV02
- D302 CV03
- D303 CV04
- D304 主軸 M166
- D305 自動運転 M305

GX Works2差分：

- 時間積算のベースクロック/特殊リレー/タイマ方式をFX3Uで確認する。
- 表示単位「分」を維持する場合、内部秒積算からの変換方式を正式化する。
- 16bit上限を超える累積時間は32bit化または飽和処理を採用する。

### 5.2 D310～D319 動作回数

ST/CY端FBの新規成立イベントで1回だけ加算する。

同一FB ON保持で連続加算しない。

相反端同時成立時は正常動作回数として加算しない。

### 5.3 D330～D351 異常回数

M701～M750の各アラーム立上りで1回だけ加算する。

ラッチ中毎スキャン加算は禁止。

### 5.4 D360～D365 診断統計

維持する。

- D360：M965新規アラーム
- D361：M967新規警告
- D362：有効RESET受付
- D363：M935復旧要求立上り
- D364：M770搬出満杯立上り
- D365：M774タクト超過立上り

## 6. GX Works2 / FX3Uで再確認する重要差分

### 6.1 Dデバイス保持範囲

FX5U向け保持前提をそのまま移植しない。

FX3Uプロジェクトで次を確認してから保持対象を確定する。

- D120
- D200～D213
- D300～D365
- 累積時間/有効件数用の新規D

保持範囲未確認の状態で「電源断後も保持する」と断定しない。

### 6.2 32bit化

長期累積値は16bit上限を超える可能性がある。

候補：

- 生産累積数
- 総サイクル時間
- CV/主軸/自動運転時間
- ST/CY動作回数
- 異常回数

最終的に32bit化する範囲を決め、必要ならDペアで管理する。

### 6.3 演算命令

GX Works2 / FX3Uで使用する以下をプロジェクト上で確認する。

- INC相当
- 32bit ADD
- 32bit DIV
- 比較
- MOV / DMOV相当
- 立上り1ショット

命令名を未確認のまま実装正本へ固定しない。

### 6.4 オーバーフロー

循環して0へ戻る設計は採用しない。

- 32bit化
- 上限飽和
- 保守時クリア

のどれを採用するかを対象値ごとに決める。

## 7. 保守統計クリア

GX Works2版でも通常RESETとは分離する。

採用する場合の最低条件：

- 自動停止中
- M938相当の設定変更許可
- 保守権限
- 確認操作
- クリア対象の明示

M183 RESET PBでD200～D365を消さない。

## 8. GX Simulator2 試験項目

- G-SIM-W2-01：M184だけではD200が増えない
- G-SIM-W2-02：M116確認後、1ワーク1回だけD200加算
- G-SIM-W2-03：M517保持でD201多重加算しない
- G-SIM-W2-04：D202/D203は自動加算しない
- G-SIM-W2-05：正常完了でD210更新
- G-SIM-W2-06：D212最大値更新
- G-SIM-W2-07：初回D213が0のまま残らない
- G-SIM-W2-08：D211平均は有効サイクルのみ
- G-SIM-W2-09：異常中断サイクルは統計除外
- G-SIM-W2-10：D210>D120でM774、M305は維持
- G-SIM-W2-11：同一端FB保持でD310～D319多重加算しない
- G-SIM-W2-12：同一アラームラッチ保持でD330～D351多重加算しない
- G-SIM-W2-13：M166 OFF中はD304を積算しない
- G-SIM-W2-14：M965 1パルスでD360 +1
- G-SIM-W2-15：M967 1パルスでD361 +1
- G-SIM-W2-16：有効RESETのみD362 +1
- G-SIM-W2-17：Section16更新がM305/M321/Yへ影響しない
- G-SIM-W2-18：D保持範囲の実設定を確認
- G-SIM-W2-19：長時間積算で16bit循環が起きない方式を確認
- G-SIM-W2-20：電源断/再起動後の保持対象を実確認

実際にGX Works2/GX Simulator2で確認するまでPASSにしない。
