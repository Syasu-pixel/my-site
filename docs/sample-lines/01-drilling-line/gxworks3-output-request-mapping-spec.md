# 01 Drilling Line — GX Works3 出力要求マッピング

Status: Draft / 教材・シミュレーション基準

## 1. 目的

`physical-io-map.md` の Y0～Y34 を、GX Works3 内部要求Mへ整理し、

`AUTO REQUEST → MANUAL REQUEST → COMMON REQUEST → ACTUAL Y`

の流れを固定する。

Yは各シーケンスから直接多重駆動せず、`ACTUAL_OUTPUT` セクションに集約する。

## 2. 基本ルール

- 自動要求：M800帯
- 手動要求：M830帯
- 共通要求：M860帯
- 実Y：Y0～Y34
- GOTはYを直接操作しない
- 手動要求も許可条件・相反条件を満たした場合だけ共通要求へ通す
- ダブルソレノイドは相反側を同時ONさせない
- 異常・安全条件喪失時は必要な共通要求を落とす
- RESETだけで自動運転・主軸運転を再開させない

自動運転ではM507主軸準備～M509復帰の工程と整合させる。

## 7. 表示灯・ブザー

表示・報知系は自動/手動の機械操作要求と分け、状態ロジックから直接一元生成する。

一次割付：

| 実Y | 機能 | 内部要求候補 |
|---|---|---|
| Y31 | 投入可表示灯 | M890 |
| Y32 | 運転表示灯 | M891 |
| Y33 | 異常表示灯 | M892 |
| Y34 | ブザー | M893 |

基準：

- M890：投入可条件 M323 を基準に生成
- M891：自動運転中 M305 を基準に生成
- M892：異常総合 M324 を基準に生成
- M893：ブザー要求 M326 かつ消音状態でないとき成立

表示灯・ブザーについてはAuto/Manualを分けない。

## 9. 共通要求生成の考え方

機械系出力は概念的に、

`(AUTO_REQUEST OR MANUAL_REQUEST) AND OUTPUT_PERMIT`

で共通要求を生成する。

ただし出力ごとに必要な許可条件は異なる。

例：

- 搬送：運転状態、区間競合、下流空き、異常なし
- ストッパー：相反側OFF、対象工程許可
- シリンダ：相反側OFF、手動/自動条件、干渉条件
- 主軸：加工工程、異常なし、通常運転許可

安全機能そのものは通常PLC出力許可ロジックで代替しない。

## 10. ACTUAL_OUTPUT セクション

最終Yはここだけで駆動する。

概念：

- M860 → Y0
- M861 → Y1
- ...
- M884 → Y30
- M890 → Y31
- M891 → Y32
- M892 → Y33
- M893 → Y34

ダブルソレノイドは、共通要求が万一同時成立した場合でも最終段で同時出力を許さない。

この最終段のインターロックは、上位ロジックの代替ではなく二重の防止策として扱う。

## 11. 手動操作との関係

GOTの手動ボタンはM900帯の要求へ書き込む。

例：

`GOT M900帯 → MANUAL section → M830～M854 → OUTPUT_REQUEST → M860～M884 → Y`

この構造により、

- GOTからYへ直接書かない
- 手動でも許可条件を通す
- 自動/手動の出力先を一本化する
- どこでブロックされたか表示できる

という構成を維持する。
