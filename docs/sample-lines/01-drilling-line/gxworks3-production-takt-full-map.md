# 01 Drilling Line — GX Works3 Section 15 PRODUCTION_TAKT 全点展開

Status: Draft / 教材・シミュレーション実装直前基準

## 1. 目的

Section 15 `PRODUCTION_TAKT` について、投入数・排出数・サイクルタイム・目標タクト・最大/最小/平均値の更新条件を、既存のD200～D213と整合させて整理する。

本仕様は生産状態の教材・シミュレーション用ロジックであり、品質判定機構が未実装の項目を確定値として扱わない。

## 2. デバイス

| Device | 用途 |
|---|---|
| D120 | 目標タクト |
| D200 | 総投入数 |
| D201 | 総排出数 |
| D202 | OK数 将来 |
| D203 | NG数 将来 |
| D210 | 直近サイクルタイム |
| D211 | 平均サイクルタイム |
| D212 | 最大サイクルタイム |
| D213 | 最小サイクルタイム |

時間単位はGX Works3実装時に正式化するまで固定しない。

## 3. D200 総投入数

投入完了PBだけで加算せず、投入受付条件と実在荷の両方を使う。

一次方針：

1. M323投入可成立
2. M184投入完了PB立上りを受付
3. CV01在荷M116成立を確認
4. 1ワークにつき1回だけD200加算

概念：

```text
accepted-load-event ----------------[ INC D200 ]
```

`accepted-load-event` 用の専用ワンショットMは、実装時に空き番号を正式割付してから使用する。

M184だけではワーク実在を保証しないため、押下だけでD200を増やさない。

## 4. D201 総排出数

加工STから実際に排出完了した時点で加算する。

一次基準：

- M515排出工程を経由
- M209 加工ST排出通過COMPLETE成立
- 加工ST在荷M140 OFFを確認
- M516→M517の完了処理で1回加算

概念：

```text
cycle-discharge-complete -----------[ INC D201 ]
```

M517が複数スキャン保持されても複数加算しないよう、完了イベントをワンショット化する。

## 5. D202 / D203 OK・NG

現行設備仕様には独立した品質判定入力がないため、D202/D203は予約のままとする。

禁止：

- D201排出数をそのままD202 OK数へコピーする。
- 異常がなかったことだけで自動的にOK判定する。

将来、測定/検査判定を追加した時点で正式な加算条件を定義する。

## 6. サイクル開始点

教材用のサイクルタイムは、加工STがワークを受け取った時点から排出完了までを基本候補とする。

一次候補：

- START：T4責任移管後、M500→M501へ遷移したイベント
- END：M517サイクル完了イベント

これにより「加工ST内サイクル」を測定できる。

ライン全体タクトや投入から排出までのリードタイムは別指標として扱う。

## 7. D210 直近サイクルタイム

サイクルSTARTで計測開始、ENDで確定する。

概念：

```text
cycle-start-event  → cycle timer start
cycle-end-event    → measured value -> D210
```

タイマ/時計デバイスの具体実装はGX Works3の採用方式に合わせる。

D210は確定した1サイクル分だけ更新し、工程途中の経過値を常時上書きしない。

## 8. D212 最大サイクルタイム

サイクル完了時だけ比較する。

```text
IF D210 > D212 THEN D212 := D210
```

初期値0の場合は最初の正常完了サイクルでD212を更新できる。

## 9. D213 最小サイクルタイム

初回サイクルの扱いに注意する。

一次方針：

- 有効サイクル件数が0 → 初回D210をD213へ格納
- 2回目以降 → D210 < D213なら更新

単純に初期値0と比較すると最小値が永遠に0になるため、初回判定を分ける。

有効サイクル件数用の内部D/Mは、D300帯等へ勝手に割付せず、実装時に正式登録する。

## 10. D211 平均サイクルタイム

平均値は累積時間/有効サイクル件数で算出する方式を基本とする。

概念：

```text
TOTAL_CYCLE_TIME += D210
VALID_CYCLE_COUNT += 1
D211 = TOTAL_CYCLE_TIME / VALID_CYCLE_COUNT
```

累積時間・件数用デバイスは未割付のため、現段階ではアルゴリズムだけ固定する。

オーバーフロー対策、32bitデータ型、保持範囲は実装前に決める。

## 11. D120 目標タクトとの比較

サイクル確定時にD210とD120を比較する。

```text
D210 > D120 → M774 タクト超過
D210 <= D120 → M774 解除候補
```

D120とD210の内部単位を同一にする。

GOTでは秒表示等へ変換する場合でも、PLC内部比較の単位を混在させない。

## 12. 異常停止サイクルの扱い

異常で中断し、サイクルが正式完了していない場合はD210/D211/D212/D213の生産統計へ通常サイクルとして加えない。

候補：

- START後にM324発生 → サイクル計測を一時中断または無効フラグ化
- 手動復旧後に同一サイクルを継続するかは、復旧仕様と整合して決める
- 完了M517まで到達しないサイクルは有効統計へ入れない

中断時間を分析したい場合は将来D300帯の停止時間統計へ分離する。

## 13. 通常停止の扱い

停止PBによる通常停止は、工程ステップ保持方針と整合させる。

サイクル途中でM305 OFFとなっても、工程再開後に同一ワークを継続する場合は、計測時間に停止時間を含めるかを明確化する必要がある。

教材用一次案：

- 生産タクト評価では停止時間を含む「実サイクル時間」を優先
- 純加工時間を別途見たい場合は将来別タイマを追加

## 14. 電源断/保持

D200/D201および統計値を電源断後に保持するかは、GX Works3のラッチ/保持設定方針と合わせて決める。

現段階では、

- 累積生産数
- 最大/最小/平均
- 目標タクト設定

について保持候補とするが、保持設定をこの資料だけで確定しない。

## 15. リセット/初期化

通常G07画面から生産数を自由に書き換えない。

統計初期化を採用する場合は、

- 保守権限
- 自動停止中
- 確認ダイアログ
- 初期化対象の明示

を別仕様で定義する。

RESET PB X3/M183はアラーム解除用であり、生産カウンタ初期化には使わない。

## 16. Section 15 擬似実装順

```text
// 15-01 load event
M323 + M184 + M116 confirmation
→ one-shot load accepted
→ D200 +1

// 15-02 cycle start
M500 -> M501 transition event
→ cycle measurement start

// 15-03 cycle end
M517 completion event
→ D201 +1
→ measured cycle -> D210

// 15-04 statistics
D210 update
→ max D212
→ min D213
→ average D211

// 15-05 takt
D210 vs D120
→ M774
```

専用イベントM/Dは未割付番号を勝手に使用せず、実装段階でデバイスコメントマスターへ登録する。

## 17. シミュレーション確認

1. 投入完了PBだけではD200が増えない。
2. M116実在荷確認後、1ワークにつきD200が1だけ増える。
3. M517保持中にD201が複数回増えない。
4. D202/D203は品質判定未実装のため自動加算されない。
5. 正常サイクル完了でD210が更新される。
6. 2サイクル目以降、D212最大値が正しく保持される。
7. 初回サイクルでD213が0のままにならない。
8. D211平均が有効サイクルだけで更新される。
9. 異常中断サイクルを正常完了統計へ加算しない。
10. D210>D120でM774が成立してもM305は自動停止しない。
