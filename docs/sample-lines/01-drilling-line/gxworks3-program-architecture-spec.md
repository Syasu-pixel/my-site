# 01 Drilling Line — GX Works3 プログラム構成 / デバイス帯仕様

Status: Draft / 教材・シミュレーション基準

## 1. 目的

E01～E18、`physical-io-map.md`、各wiring scheduleで確定した物理I/Oを、GX Works3のプログラム構成・内部デバイス・コメント体系へ接続する。

本資料は教材・シミュレーション用の制御設計基準である。実機では安全機能を通常PLCロジックだけで成立させず、非常停止、安全扉、ライトカーテン等は別の安全回路・安全機器で成立させる。通常PLC側で安全信号を無効化・迂回するロジックは作らない。

## 2. 基本ルール

- CPU：FX5U-64MT/ES
- Engineering：GX Works3
- 物理I/O：`physical-io-map.md` を正とする
- X入力を直接各シーケンスへ多用せず、入力処理で内部Mへ受ける
- Y出力は各機能から直接多重駆動せず、最終出力処理へ集約する
- ダブルコイルを作らない
- 自動要求 / 手動要求 / 共通要求 / 実Yを分離する
- 通過検出は「ONを一度確認した後のOFF」で成立させる
- タイマは工程遷移の主条件ではなく、待ち時間・監視時間に限定する
- 各アクチュエータは指令後に対応フィードバックを確認して次工程へ進む
- RESETで自動再起動させない
- 異常復帰後も、自動運転再開には運転準備・自動起動操作を必要とする

## 3. プログラムセクション

GX Works3内では以下の順序を基準とする。

| No. | Section | 内容 |
|---:|---|---|
| 00 | INPUT_PROCESS | 物理X → 内部入力M、押しボタンエッジ処理 |
| 01 | PASSAGE_DETECT | 通過センサON確認 → 立下り検出 |
| 02 | COMMON_SAFETY_MON | 安全監視・エア圧・共通成立条件 |
| 03 | MODE_RUN | 手動/自動、運転準備、起動・停止 |
| 04 | TRANSFER_CV12 | CV01→CV02 搬送 |
| 05 | TRANSFER_CV23 | CV02→CV03 搬送 |
| 06 | TRANSFER_CV34 | CV03→CV04 搬送 |
| 07 | TRANSFER_CV4ST | CV04→加工ST 搬送 |
| 08 | PROCESS_AUTO | 加工ST M500～M517 |
| 09 | MANUAL | GOT/手動要求生成 |
| 10 | OUTPUT_REQUEST | 自動・手動要求 → 共通要求 |
| 11 | ACTUAL_OUTPUT | 共通要求・相反インターロック → Y |
| 12 | TIMEOUT_FAULT | タイムアウト・不一致・異常ラッチ |
| 13 | WARNING_BUZZER | 警告・表示・ブザー管理 |
| 14 | GOT_INTERFACE | GOT表示/操作用M・D |
| 15 | PRODUCTION_TAKT | 個数・サイクルタイム・タクト |
| 16 | MAINTENANCE | 保守表示・試運転用状態（安全機能の迂回は禁止） |

## 4. 内部Mデバイス帯

### M100～M199 — 入力処理

例：

| M | コメント | 元X |
|---|---|---|
| M100 | 運転準備PB | X0 |
| M101 | 自動起動PB | X1 |
| M102 | 停止PB | X2 |
| M103 | RESET PB | X3 |
| M104 | 投入完了PB | X4 |
| M105 | 手動モードSW | X5 |
| M106 | 自動モードSW | X6 |
| M107 | ブザー停止PB | X7 |
| M110 | 安全回路OK | X10 |
| M111 | エア圧OK | X11 |
| M112 | 非常停止系正常監視 | X12 |
| M113 | 安全扉閉 | X13 |
| M114 | ライトカーテンクリア | X14 |
| M115 | 安全リレー正常 | X15 |
| M116～ | 搬送・加工・INV・主軸入力 | X16以降 |

全56入力をこの帯へ対応させる。予備X70～X77は、正式用途が決まるまで内部Mを固定割当しなくてもよい。

## 5. M200～M299 — 通過・エッジ・状態記憶

通過センサはOFFだけで通過完了とみなさない。

各通過点について、

1. 対応センサONを確認
2. `SEEN` をセット
3. その後センサOFFを確認
4. `PASS_COMPLETE` を1スキャンまたは所定の内部フラグとして成立
5. 工程完了後にSEENをクリア

とする。

例：

- M200：CV01 passage seen
- M201：CV01 passage complete
- M202：CV02 passage seen
- M203：CV02 passage complete
- M204：CV03 passage seen
- M205：CV03 passage complete
- M206：CV04 passage seen
- M207：CV04 passage complete
- M208：加工ST排出 passage seen
- M209：加工ST排出 passage complete

## 6. M300～M399 — 共通 / モード / 運転

基準：

- M300：手動モード成立
- M301：自動モード成立
- M305：自動運転中
- M310：停止要求
- M320：運転準備条件成立
- M321：運転準備ラッチ
- M322：自動起動可能
- M323：投入可条件
- M324：異常総合
- M325：警告総合
- M326：ブザー要求
- M327：ブザー消音状態
- M330：加工ST受入許可

運転準備条件 M320 は、安全監視・エア圧・主要原位置・異常状態などを組み合わせて生成する。

M321は物理「運転準備PB」でラッチするが、異常・安全条件喪失では解除する。

M305は自動起動PBで成立し、通常停止PBではM305のみ解除する。健全状態ならM321は保持し、再度自動起動PBで再開できる。

安全監視喪失・重大異常ではM305とM321をともに解除する。

## 7. M400～M499 — 搬送制御

4搬送区間を独立した同一パターンで構成する。

- CV01→CV02
- CV02→CV03
- CV03→CV04
- CV04→加工ST

基準状態：

- M430：CV01→02 transfer busy
- M431：CV02→03 transfer busy
- M432：CV03→04 transfer busy
- M433：CV04→ST transfer busy

搬送開始条件の考え方：

- 自動運転中 M305
- 搬送元にワークあり
- 搬送先が空き
- 該当区間の許可成立
- 隣接区間が動作中でない
- 非隣接区間は同時運転可
- CV04→加工STはM330成立が必要

搬送完了は、

- 搬送元通過センサの passage complete
- 搬送元在荷OFF
- 搬送先在荷ON

の組合せを基本とする。

タイムアウトは別Section 12で監視し、目安5秒を暫定設定値としてDデバイス化する。

## 8. M500～M517 — 加工ステップ

加工STは1ステップ1Mを基準とする。

| Step | M | 内容 |
|---:|---|---|
| 500 | M500 | 加工ST待機 |
| 501 | M501 | 搬入 |
| 502 | M502 | ST05停止 |
| 503 | M503 | 搬送面切替 |
| 504 | M504 | 横移載 |
| 505 | M505 | 位置決め |
| 506 | M506 | クランプ |
| 507 | M507 | 主軸準備 |
| 508 | M508 | 穴あけ |
| 509 | M509 | ドリル復帰 |
| 510 | M510 | クランプ解除 |
| 511 | M511 | 位置決め解除 |
| 512 | M512 | 搬送面へ戻し |
| 513 | M513 | 搬送面復帰 |
| 514 | M514 | 排出準備 |
| 515 | M515 | 排出 |

## 10. M800～M899 — 出力要求

自動要求、手動要求、共通要求を分ける。

### 自動要求

- M800～M803：CV01～04 RUN auto
- M804以降：ST01～05 auto
- M814～M823：CY01～05 auto
- M824：主軸 RUN auto

### 手動要求

- M830～M833：CV01～04 RUN manual
- M834以降：ST01～05 manual
- M844～M853：CY01～05 manual
- M854：主軸 RUN manual

### 共通要求

- M860～M863：CV01～04 RUN common
- M864以降：ST01～05 common
- M874～M883：CY01～05 common
- M884：主軸 RUN common

共通要求は、モード・許可・相反条件を満たしたときだけ成立させる。

## 11. M900～M999 — GOTインターフェース

GOTからYへ直接書き込まない。

GOT操作は要求Mのみを操作し、PLC側で条件確認後にM830～M854等の手動要求へ変換する。

例：

- M900～：画面操作要求
- M920～：画面表示状態
- M940～：ブロック理由表示
- M960～：アラーム確認/履歴補助

手動画面では、各機構について

- 指令状態
- 原位置フィードバック
- 動作位置フィードバック
- 操作不可理由

を同時表示する。

## 13. 実出力Yの集約

Y0～Y34はSection 11のみで最終駆動する基準とする。

例：

`Auto Request OR Manual Request`
→ 共通許可
→ 相反インターロック
→ 異常/停止条件
→ Common Request
→ Actual Y

ダブルソレノイドは必ずペアで相互排他とする。

対象：

- Y4 / Y5 ST01
- Y6 / Y7 ST02
- Y10 / Y11 ST03
- Y12 / Y13 ST04
- Y14 / Y15 ST05
- Y16 / Y17 CY01
- Y20 / Y21 CY02
- Y22 / Y23 CY03
- Y24 / Y25 CY04
- Y26 / Y27 CY05

両方向要求が同時成立した場合は、両YをOFFにして診断対象とする。

## 14. 加工主軸の扱い

Y30は主軸ドライブへの通常RUN要求であり、主回路を直接開閉する出力ではない。

加工送り許可には少なくとも、

- 加工治具在荷
- 位置決め成立
- クランプ成立
- 主軸運転確認

を必要とする。

主軸停止確認方法は別仕様でTBDのため、X66「運転確認」だけを真のゼロ速度検出とみなさない。将来ゼロ速度/停止確認信号を追加する場合は、X70～X77の予備入力候補から正式割付し、物理I/O・E10・E18・GX Works3コメントを同時更新する。

## 15. コメント命名基準

GX Works3のデバイスコメントは、短くても意味が一意になる名称を使う。

例：

- `CV01_在荷`
- `CV01_通過Seen`
- `CV01to02_搬送中`
- `CY04_ClampReq`
- `PROC_S508_穴あけ`
- `ALM_A201_CY01`
- `GOT_CY01_HOME_REQ`

日本語説明とタグを混在させてもよいが、同じ概念に複数の名称を作らない。
