# 01 Drilling Line — GX Works3 Section 08 PROCESS_AUTO ネットワーク実装順

Status: Draft / 教材・シミュレーション実装直前基準

## 1. 目的

`gxworks3-process-step-spec.md` と `gxworks3-process-auto-output-map.md` を基準に、加工ステーション M500～M517 を GX Works3 へ入力しやすいネットワーク順へ展開する。

本資料は教材・シミュレーション用の通常PLCロジック仕様である。安全機能そのものは通常PLCで成立させず、安全回路から返る監視状態を通常運転許可へ使用する。

## 2. Section 08 共通原則

- M500～M517 は原則 one-hot とし、正常時は1ステップだけ成立する。
- ステップ遷移は `現在ステップ + 完了FB + 共通進行許可` を確認してから行う。
- 時間だけで機構を次工程へ進めない。
- AUTO要求は M812～M824 を使用し、Yを本Sectionから直接駆動しない。
- M324 異常総合成立中は新しい正常遷移を進めない。
- M305 OFF時は現在ステップを原則保持し、勝手にM500へ戻さない。
- RESETだけで次ステップへ進めない。
- 位置不整合時は手動復旧を経て、必要に応じてM500へ戻す。
- ダブルソレノイドの保持/パルス方式はバルブ正式仕様確定後に最終化する。

共通進行条件の概念：

```text
PROCESS_ADVANCE_OK =
    M305
AND M321
AND NOT M324
```

専用Mを使う場合はデバイスコメントマスターへ正式登録してから採用する。現段階では未登録Mを新設しない。

## 3. 初期状態 / one-hot監視

### Network 08-001 — 初期M500成立

教材・シミュレーション初期化時のみ、加工ステップが一つも成立していないことを確認してM500を初期状態とする候補。

通常のRESETや停止操作ではこのネットワークを再実行しない。

```text
initialization-condition
AND NOT (M500 OR M501 OR ... OR M517)
----------------------------------( SET M500 )
```

### Network 08-002 — 複数ステップ成立監視

M500～M517の複数同時成立は正常状態として扱わない。

具体的な診断M/アラームコードは未割付のため、現段階では監査項目として残す。既存M700帯へ勝手に新規コードを追加しない。

## 4. M500 WAIT

### Network 08-500A — WAIT基準出力要求

M500では加工STの基準状態要求を生成する。

```text
M500 -----------------------------( M812 )  ST05 UP
M500 -----------------------------( M814 )  CY01 HOME
M500 -----------------------------( M816 )  CY02 BACK
M500 -----------------------------( M818 )  CY03 RELEASE
M500 -----------------------------( M820 )  CY04 RELEASE
M500 -----------------------------( M822 )  CY05 UP
```

M824主軸RUNはM500では生成しない。

### Network 08-500B — T4受入確認

M500からM501へ進む条件：

- PROCESS_ADVANCE_OK
- T4完了後の加工ST在荷 M140
- ST05上昇端 M136
- CY01搬送面復帰端 M142
- CY02後退端 M144
- CY03解除端 M146
- CY04解除端 M150
- CY05上昇端 M152
- 主軸異常 M167 OFF

```text
M500
AND PROCESS_ADVANCE_OK
AND M140
AND M136
AND M142 AND M144 AND M146 AND M150 AND M152
AND NOT M167
----------------------------------( SET M501 )
----------------------------------( RST M500 )
```

T4 Busy解除のタイミングと同一スキャン競合が出る場合は、M140成立を加工ST側の受入正本として扱い、シミュレーションで確認する。

## 23. 異常時の扱い

M324成立時：

- 正常ステップ遷移を停止する。
- 現在M500～M517を無条件でRESETしない。
- AUTO要求はSection 10/11の共通停止条件と整合させる。
- 原因復旧とRESET後も自動起動しない。
- 現在位置とステップが一致すれば再開候補。
- 不一致ならG04手動復旧を使用し、基準位置へ戻す。

安全監視喪失時も同様に通常自動進行を止めるが、安全機能そのものの停止・復帰は安全回路側を正とする。

## 24. 通常停止時の扱い

停止PBでM305 OFFとなった場合：

- 現在ステップを保持。
- 新規ステップ遷移を行わない。
- 出力継続/解除は各COMMON出力ポリシーに従う。
- 再起動前に現在FBと現在ステップの整合を確認する。

RESETと通常停止を混同しない。

## 25. シミュレーション確認

最低限、以下を確認する。

1. M500～M517が正常時one-hotになる。
2. T4完了後M140成立でM500→M501へ進む。
3. 各シリンダは期待端成立前に次ステップへ進まない。
4. M504はM145だけでなくM141も必要。
5. M507はM166確認前にM508へ進まない。
6. M508はM153確認前にD112滞留完了だけで進まない。
7. M509はM152成立前に主軸RUN要求を解除しない。
8. M514はM154搬出満杯中にM515へ進まない。
9. M515はM209 COMPLETE前にM516へ進まない。
10. M516は加工STワーク不在確認前にM517へ進まない。
11. M517完了イベントが1サイクル1回になる。
12. M324成立時にステップを勝手にM500へ初期化しない。
13. 停止PB後、再起動だけで位置不整合工程が進まない。
14. RESETからM305/M321を自動SETしない。
