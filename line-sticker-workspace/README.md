# LINEスタンプ 一時保管

採用済みグリーンバック・マスターを一時保管する作業領域です。

## 制作・登録フロー

1. 制作中は、1商品につき **4×6＝24スタンプのグリーンバック・マスター1枚**を確認用として作る。
2. ユーザーが採用したマスターだけを、この一時保管領域へ保存する。
3. ユーザーが「溜めたものを登録していこう」と指示した段階で、採用マスターから透過・24枚切り出しを行う。
4. LINE登録用の **24スタンプ＋main＋tab＝26 PNG** を作成し、ZIPにまとめて提出する。
5. ZIP作成時点では元のグリーンバック・マスターを削除しない。修正・再生成に戻れる状態を維持する。
6. LINE Creators Marketへの登録完了をユーザーが確認した商品だけ、一時保管していた元マスターを削除する。
7. 一時保管領域には「まだLINE登録が完了していない商品」だけを残す。

## マスター配置の絶対条件

- LINEスタンプ24個のグリーンバック・マスターは、**横6列 × 縦4行 ＝ 24個**で固定する。
- 「4×6」だけの曖昧な表記で判断せず、必ず **横6・縦4** と明記して確認する。
- **横4列 × 縦6行は禁止**。生成前と生成後の両方で列数・行数を目視確認する。
- 背景は全面均一のグリーン。セル境界線は描かない。
- 各セル相当領域には十分な余白を取り、隣のスタンプ要素を侵入させない。

## 魚シリーズの24個ストーリー構成

- 魚シリーズは、各スタンプ単体でも会話に使えることを優先しつつ、24個を通して見ると「一回の釣行」が自然に流れる構成を基本とする。
- 基本の流れは、**「○○釣り行こうぜ！」などの誘い → 準備・出発 → 釣れた／よっしゃ／ちっさ／入れ食い／バレた等の釣行ネタ → その魚固有のあるある・シュール／狂気ちょい入りネタ → 料理・食ネタ → また釣りに行こう → おつかれさま** とする。
- 魚種ごとの特徴、釣り方、食べ方を優先し、魚を差し替えただけの同一24文言にはしない。
- シュール／狂気要素はグロテスクにせず、「魚本人が自分の料理を喜ぶ」など、思わず目に留まるコミカルな方向にする。
- ストーリー性のために日常で使いにくい文言ばかりにせず、実用性と魚種固有ネタの両方を残す。

## ライブ対話時の画像確認

- ライブ対話でマスター画像を作成した場合は、生成完了だけで提示完了としない。
- ライブ対話では、今回表示成功を確認した **画像生成からチャット内へ直接表示する経路** を標準ルートとして使い、マスター画像をユーザーが目視確認できる状態にする。別経路で「生成済み」と報告するだけでは提示完了としない。
- ユーザーが「見えている」ことを確認するまでは、採用・GitHub一時保管・次工程へ進めない。
- 表示されない場合は、説明だけで代替して採用扱いにせず、画像を再提示して確認できる状態を作る。
- 通常チャットとライブ対話では表示経路が異なる場合があるため、ライブ時はライブで実際に表示できた経路を優先する。

## 制作上の注意

- 隣セルへ要素をはみ出させない。
- 透過時に欠け・緑フリンジ・ゴミになりやすい極細線や小さすぎる独立装飾は避ける。
- 意味はキャラクターの表情・ポーズ、大きな文字、透過に耐える大きめの小物を中心に表現する。
- 本番サイト公開用の領域ではない。mainへ混入させない。
